# @deepseek-ai/dsh-tool-conductor

English | [中文](README.zh.md)

The model-facing Conductor tool (`conductor`). It requires an objective, purpose, A/B/C entry and mandate-owner attribution; new runs also require an intake rationale, and analysis requires answer/recommendations and at least one measurable `acceptanceCriteria` item before any specialist starts. Constraints describe limits; deliverable requirements belong in acceptance criteria. Other inputs include cited material selectors and a resume id. Code admits the route and spawns a fresh structured-output specialist at each applicable stage. The model cannot grant write, quality-execution, or closeout authority. After Gate C validates an exact baseline, the tool asks the host approval seam once with the baseline hash, canonical paths, selected command bindings, and required effect profile; rejection, cancellation, or unavailable approval stops before any write-capable or quality child starts. It returns an implementation GO/NO-GO, an audited analysis report or a blocker; a GO never commits, pushes, merges, or deploys on its own.

The state machine, gate engine, and Session-log persistence live in [`@deepseek-ai/dsh-conductor`](../conductor/README.md); the specialist role skills come from [`@deepseek-ai/dsh-conductor-presets`](../conductor-presets/README.md). Every stage runs as a one-agent workflow over the existing workflow engine. The runtime loads the stage role plus `conductor-specialist`, requires structured output, and applies both a name-level tool allowlist and an argument-aware guard in the child executor. Write targets are canonicalized before Headsman `allowed_paths`/`excluded_paths` checks; Integrator is further limited to `docs` and `.agents/notes`.

`qualityCommands` is an empty-by-default deployment catalog. Each entry supplies an opaque id, safe description, exact argv, permitted stage, cwd, confinement mode, and resource limits. Its immutable definition hash includes the filesystem effect, mandatory `network: deny`, and `external: none`; Gate C binds the selected ids and definition hashes into the execution baseline. The private child tool `conductor_quality_check` accepts exactly one `command_id`; it never accepts command text or extra arguments, invokes only the exact bound argv, requires a matching host authorization and `SandboxEnforcement: full` for that concrete filesystem-and-network policy, collects bounded output without spill files, and stores only execution facts and output digests in a durable `QualityExecutionRecord`. Headsman and its Ralph rounds may produce Gate-D records; the fresh Auditor must rerun the Gate-E bindings independently. The selected provider must therefore support trusted child tool contributions in addition to the other child policies.

When `maxRalphRounds` is positive, Headsman calls the shared Ralph workflow runner with the same child policy. Every fresh round receives the approved execution baseline, acceptance criteria, constraints, and the bound Gate-D command ids with their model-safe descriptions, then Headsman still returns an ImplementationReport for Gate D and independent Auditor review. A Gate-G GO is persisted as `awaiting_authorization`. The model-facing tool cannot close the run or supply structured closeout authorization; a host may later call the core `closeRun` API with explicit authorization and evidence. Conductor never performs the release action itself.

`routeTasks` defaults to `false`; the shipped Conductor preset enables it. For each new parent task, only `conductor` is offered before dispatch and an executor guard denies other calls, regardless of workspace instructions. A turn ending without dispatch fails explicitly. While dispatch runs and after any result, including an Arbiter GO or reported analysis, all parent tools and automatic redispatch are denied; the parent reports the outcome and stops. A new user turn or steering message resets routing to allow only `conductor`; plugin context alone does not. Specialist sessions retain their stage-specific policies. Other presets and the general instruction loader are unaffected.

The first call proposes `purpose: implementation | analysis`, `entry: detective | strategist | devils-advocate`, rationale and source selectors; analysis additionally selects `deliverable: answer | recommendations`. `current-request` identifies the actual user message. `materialFiles` contains only normalized workspace-relative files explicitly cited there; `scopeSources` and `planSources` cite those selectors, not model-invented ids. Runtime captures full bounded UTF-8 inputs and hashes through the filesystem service, rejects path escapes/substitution, checkpoints admission before dispatch, and reuses captured inputs on resume. `maxMaterialFiles` defaults to 16, `maxMaterialBytes` to 65536 per input and `maxMaterialTotalBytes` to 262144 for serialized admission; each is a validated positive safe integer.

Analysis uses the admitted producer → Auditor → Arbiter, with Strategist producing recommendations that enter at Detective. The dispatch includes the unchanged `acceptance_criteria`, an instruction to copy them verbatim in order, and `gate_history` with rework reasons. A mismatched candidate receives the complete expected list plus missing, extra and changed criteria for repair. Child filters and executor guards deny writes, shell, quality commands, approvals and external effects, independently of prompts. Arbiter `accept | revise | blocked` binds the exact candidate/audit; acceptance is terminal `reported`, never GO or host approval. A revision requires a new producer version and audit. Implementation retains its execution-C approval and quality/closeout policies. [The intake decision](../../../.agents/notes/implemented/feature/2026-10-25-conductor-intake-and-report-completion.md) specifies routes, causal rework and format 3.

`maxReworkPerGate` is a validated positive safe integer, defaulting to 2; the shipped preset also sets 2. Report-format and baseline-proposal errors retry the same role within that gate's budget, including Arbiter report repair. The specialist schema omits `allowedPaths` and `excludedPaths`; runtime inserts the run's owner paths and exclusions without widening them. Specialist-written path fields are report errors, while host-binding or authority forgery stops immediately. A workflow or transport failure propagates after checkpointing completed host quality records, without inventing a specialist envelope or gate verdict. Only completed work without a valid report enters report repair.

Decision, report and blocked results include `runId`, reached `stage`, lifecycle status, complete `gateHistory` with reasons, and `specialistsRan` derived from runtime gate attempts, including rejected reports. Errors before run creation explicitly state that no Conductor run was started; an error after creation includes the last durable run status and a failed child known to have started, without inventing a gate verdict. These diagnostics do not convert a report, a blocked run, or an Arbiter GO into permission to act.

Each workflow dispatch records a model-hidden child identity and lifecycle in the parent log. The runtime binds a saved evaluated gate to that child's dispatch history offset, leaving every rework attempt separate. Ralph's trusted workflow observer supplies worker identities without assigning Headsman's Gate D to a worker. These events do not affect prompts, gate decisions or authority; [the presentation decision](../../../.agents/notes/implemented/bug-fix/2026-10-28-conductor-child-role-status.md) owns their semantics.

## Known Limitations and Deferred Work

Skill lookup selects the parent agent's scope key, so its preset's installed role and protocol providers remain visible independently of the task workspace. The shipped preset validates these resources before mounting; a custom composition must provide its own complete skill catalog.

- The selected subagent provider must support structured output, tool filtering, trusted tool guards, trusted child tool contributions, and per-child personas; unsupported providers fail at tool load.
- Quality execution fails closed when the host has no sandbox backend that fully enforces the command's filesystem mode and network denial.
- `workspace-write` grants the command's configured write root; backend-owned temporary files needed to launch the confined process are outside that product write root.
- Auditor entry, verification purpose, dirty digests and non-Git manifests are unsupported Phase 2 inputs.
- Closeout is record-only. Commit, push, merge, publish, and deploy remain external owner-controlled operations.
