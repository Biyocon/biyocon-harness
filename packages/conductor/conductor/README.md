# @deepseek-ai/dsh-conductor

English | [中文](README.zh.md)

The Conductor runtime owns run state, gates A–G, defect-class rework routing, source and execution baselines, and explicit closeout records. `SessionConductorRunStore` appends a complete keyed checkpoint to the parent Session log and flushes after each transition; resume accepts only the last documented gate state and rejects terminal or escalated runs. Pre-release records carry an explicit format version and unsupported records are rejected without migration.

Implementation specialists return `SpecialistEnvelope` values to Conductor and never choose the next specialist. Gate C proposes an immutable execution baseline containing deployment-resolved quality-command bindings and their definition hashes. Before Gate C can pass, the host must authorize the exact baseline hash and its effect profile: workspace writes when implementation is required, catalog quality execution when commands are bound, and no external effects. Rejection or an unavailable approval provider blocks the run before Headsman starts. Approved baselines remain in append-only history; scope or plan rework clears only the active baseline and authorization, preserving earlier evidence without allowing it to satisfy a later baseline.

Headsman and Auditor cite exactly the durable `QualityExecutionRecord` ids produced by their current dispatch rather than command text or earlier evidence. Gate D and Gate E each require fresh passing evidence for every command bound to that gate, and Gate E accepts only evidence produced by its independent Auditor cycle. Gate G records the Arbiter decision, and a GO remains `awaiting_authorization` until the mandate owner supplies outcome evidence and traceability through the host-owned closeout API. The runtime records closeout but performs no commit, push, merge, or deploy action. `ConductorAuthority` identifies the mandate owner only; it grants no execution or external-action capability.

`maxReworkPerGate` limits rework decisions independently at each `GateRecord.gate` (default 2). A third requested rework at the same gate escalates when that limit is 2; another gate's decisions do not consume its budget. Structurally invalid envelopes, Arbiter decisions, and Gate C baselines return to the reporting role with defect class `report`; invalid reports are not retained as validated specialist reports. Identity, assessed-baseline, routing, evidence, or authority violations and rejected host approval escalate immediately. Ralph rounds have their own unchanged limit.

The Gate C proposal contains versions, rollback reference, and requested quality-command ids, without path fields. Runtime supplies `allowedPaths` and `excludedPaths` from the owner-authorized run and rejects specialist-written paths. The complete resolved baseline still requires exact host approval. `SpecialistExecutionFailure` propagates infrastructure faults after checkpointing completed host quality records, without fabricating a specialist report or gate verdict. Record format 4 persists immutable intake, evaluated/skipped history, causal repairs and report versions alongside implementation evidence; format 3 and older records are rejected explicitly without migration. [The gate-robustness decision](../../../.agents/notes/implemented/bug-fix/2026-10-25-conductor-gate-robustness.md) records the validation distinction and verification.

The admitted purpose is `implementation | analysis`, with entry at Detective, Strategist or Devil's Advocate. Analysis requires `answer | recommendations` and a nonempty list of distinct, normalized `acceptanceCriteria` strings at creation and durable load: answer uses the selected producer → Auditor → Arbiter; recommendations entering Detective additionally require Strategist as producer. Supplied-work and inapplicable gates are recorded as `kind: skipped`, never approvals. Rework returns to the missing prerequisite and then its requesting gate, reusing the per-gate budget. Admission captures current user text and explicitly cited workspace text files with content hashes; resume validates that captured route and material. Later implementation entry without an explicitly supplied source baseline reworks to Detective; an input-content hash is never a source baseline.

Analysis retains null execution state and no quality work. A versioned report is audited independently before Arbiter returns `accept | revise | blocked`; acceptance ends in `reported`/`report-complete`, not GO or closeout. It never requests approval or visits Headsman, Ralph or Integrator. [The intake decision](../../../.agents/notes/implemented/feature/2026-10-25-conductor-intake-and-report-completion.md) owns provenance, report binding and deferred Phase 2 behavior.

`conductor/child` is a model-hidden parent event for one concrete workflow child: runtime role, per-role attempt, lifecycle, dispatch history offset and optional exact-child gate verdict. The `./child-types` export is safe for clients. Mount this package as a plugin alongside `sessionProjections` to retain the `conductorChildren` projection independently of agent lifetime; the shared base bundle does so. Inherited seed children are cleared. These required-on-read events do not change checkpoint format 4. [The child-presentation decision](../../../.agents/notes/implemented/bug-fix/2026-10-28-conductor-child-role-status.md) defines attribution and replay semantics.

Owner interactions use a separate append-only ledger bound to the root session, originating gate, exact child attempt and report hash. A monotonic owner revision binds complete answers and single-use reassessment plans; original admission and historical baselines remain unchanged. `maxOwnerReassessmentsPerGate` defaults to 2, is independent of automatic rework, and is persisted per run. A third owner-directed assessment at one gate is terminal. Free text grants no authority; a concrete host-capability-checked amendment invalidates active authorization and requires fresh Gate C approval. Analysis accepts read-only clarification only. Pending questions have no automatic expiry. Production runs remain `awaiting_owner` until P3 supplies the UI; ordinary model-directed resume refuses pending questions and answers. The scoped host controller uses scripted host responses for tests. Four required-on-read events record question creation, response, continuation consumption and terminal rejection before the complete checkpoint; none is ignorable. Decoding validates event/ledger identity and transport bindings. Recovery reconciles complete owner facts after an interrupted checkpoint write without reapplying a response or dispatching. A consumed plan with no later gate settlement cannot be resumed speculatively. The record remains version 4; this adds session vocabulary without migrating older run records. [The owner-escalation proposal](../../../.agents/notes/proposed/feature/2026-10-30-conductor-owner-escalation-resumption.md) remains proposed until P3.

## Known Limitations and Deferred Work

- Checkpoints are durable only when the host mounts a persistent Session provider; an in-memory Session retains them only for that process lifetime.
- Conductor records an authorized external closeout action and its evidence but deliberately does not execute release operations.
