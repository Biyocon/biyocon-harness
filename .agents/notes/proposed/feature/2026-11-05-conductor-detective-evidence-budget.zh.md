# Agent Note: Detective 的结果成本与证据

Status: proposed

[English](2026-11-05-conductor-detective-evidence-budget.md) | 中文

## Problem

[Issue #58](https://github.com/Biyocon/biyocon-harness/issues/58)报告 Detective 分析大型目录时约用了 472,000 token。所有者的目标是降低完整分析的 DeepSeek 账单。下方经批准的本地测量表明，大部分输入 token 命中了便宜的缓存，而大体积搜索结果首次进入时属于昂贵的非缓存输入，之后又在历史中重复。单纯设限只会提前终止分析；节省费用时仍须标示遗漏，并保留批评者与 Auditor 的证据。

当前的[分派](../../../../packages/conductor/tool-conductor/src/index.ts)会把完整的 v5 `admission`（包括已捕获文件正文）放入 Detective 提示。子会话也可用 `glob`、`grep` 和 `read` 发现工作区文件。后续每次模型请求都会从会话重建完整的模型可见历史；现有[工具结果裁剪器](../../../../packages/compaction/compaction-tool-result-pruner/src/index.ts)仅在上下文压力或溢出触发压缩时运行。所测子会话没有裁剪事件。[批评者](../../../../packages/conductor/tool-conductor/src/analysis-dispatch.ts)接收绑定候选报告的摘录，且拥有独立的实测预算；本提案不削减其输入或 Auditor 的访问能力。

## Proposal

### 阶段 A：在来源处限制结果，不改变 v5 运行记录

主要通过限制 `glob` 和 `grep` 结果降低价格。验证仅用于 Detective 的 Config 字段（`detectiveGlobMaxResultChars`、`detectiveGrepMaxResultChars`），各初设 4,000 字符，覆盖含标题及继续标记的完整结果，并保留已有条目/单行上限。每页报告 `truncated`、显示数/总数、稳定继续游标及路径/行身份。每个只读页面及快照摘要均记录为工具结果。分页保留完整、不可变的搜索快照，否则明确失败。仍可缩小查询；未返回条目不能算作已检查。宽泛的 `glob` 页面优先采用现有顶层采样以显示其他子树。较小的 `read` 窗口单独评估；`offset` 已提供继续机制。

[搜索 Config](../../../../packages/fs/tool-fs-search/src/index.ts)验证 `globMaxResults`（100 个路径）、`grepMaxMatches`（250 个匹配）、`grepMaxLineBytes`（2,000 字节）、`searchMetaMaxBytes`（65,536 字节）及原始输出上限。[读取 Config](../../../../packages/fs/tool-fs/src/index.ts)验证 `readLimit`（2,000 行）、`readMaxLineLength`（2,000 字符）及 `readMaxBytes`（51,200 字节），并报告截断、支持 `offset`。搜索在条目超限时保存完整格式化结果，但缺少字符上限与游标分页。[通用 spill 策略](../../../../packages/spill/spill-policy/src/index.ts)验证 `maxInlineBytes`，但仅尽力保存、跳过面向模型的 `read`，且没有稳定分页。这些全局插件设置会影响其他角色。将可信的 `childToolContribution` 从 `runSpecialist` 经 `dispatchAnalysisChild` 的 producer 分支传入 `runWorkflowChild`，注册限定于 Detective 的搜索定义并遮蔽继承工具。不支持 `toolContribution` 的 provider 必须拒绝。字符上限与游标需要工具/Conductor 代码，但无需改 agent-loop。新上限须验证为正安全整数，并足以容纳固定的页面标题及继续标记。完整结果与游标须留在子会话拥有的会话证据中，以免冷恢复后对已变化文件重新解释某页。

在 v5 记录中保留完整且经哈希验证的[准入捕获](../../../../packages/conductor/conductor/src/types.ts)。作为较小的独立改进，从已有的 `id`、`selector`、`sha256` 和 `content` 派生已捕获文件的有序索引；字节数和行数现算，不增加记录字段。初始提示发送当前请求和索引，不发送文件正文。限定于该子会话的捕获读取工具使用独立、可信的工具名称，同时由 Detective producer 的 `childToolFilter` 和 analysis guard 允许，不扩展其他角色的 `READ_TOOLS`。它从捕获 `content` 返回有界行范围，验证哈希，并通过现有工具调用/结果事件记录参数及文本；它绝不以变化后的工作区文件代替准入内容。未知 ID 或过大的范围明确报错。UI 渲染意图为 `generic`，`locations` 仅由请求的 selector 和行号决定。

在来源处限制结果会追加较短的工具结果，不重写先前模型可见消息，因此保留缓存前缀的复用机会。阶段 A 沿用现有会话事件类型，v5 `ConductorRun` 字段不变。工具返回的工作区发现项不会因此获得准入 material ID 或引用资格。完整捕获继续供批评者验证摘录及 Auditor 检查。报告须披露未检查材料；阶段 A 不声称已有宿主拥有的持久覆盖台账或新终态。

### 阶段 B：v6 用量核算与明确的不完整终态

为每次 Detective 尝试增加宿主拥有的覆盖台账：准入材料的检查情况及准确范围、已发现工作区来源及可取得的版本或摘要、选择原因，以及影响结论的遗漏。只有准确的来源片段算作已检查证据。准入时保存经验证的每请求输入、包含推理的输出以及每运行总 token 上限。预检包含 persona、系统文本、工具 schema、下一份输入及已记录的模型可见历史；把 provider 报告的非缓存输入、缓存读取/写入和输出作为互不重叠的计数，推理包含在输出中。dispatch 前须针对共享运行额度原子持久化每次模型调用的唯一预留，避免并发调用重复预留同一剩余额度。恢复时，须在下一次调用前幂等核对每笔预留；用量未知或无效时消耗该预留，并以 `incomplete` 结束运行；provider 超额则终止运行并披露。返工和所有者继续执行共用保留的运行额度。与[子智能体累计输出上限](../../implemented/architecture/2026-11-02-reserved-child-identity-and-output-token-limit.md)组合：有效输出上限取每请求上限、子智能体剩余累计输出额度和预留输入后运行剩余额度三者中的最小值。输出含推理，只对运行预算记账一次。

如果剩余额度不足以检查相关证据，记录已消耗/已预留/上限和遗漏范围，以终态 `incomplete` 结束。不得把它作为完整候选交给批评者、暗中重置额度，或转换成全面的 `ready` 报告。这是有界的失败状态，不是效率收益。

这些新增的运行字段和终态语义需要新的记录版本。与 [#30 第二阶段](https://github.com/Biyocon/biyocon-harness/issues/30)协调统一的 v6 归属和 schema；该阶段还计划 Auditor 入口、verification、未提交文件摘要及 Git 外文件清单。若 #30 先交付 v6，阶段 B 使用下一个版本。#30 清单可为新发现的文件提供稳定来源；在它出现之前，发现项仍属临时材料。

两个阶段均保留只读分析、生产者依据完整准入捕获填写的 `material_spans`、必经批评、Auditor 可用的全部证据，以及既有 Gate C/GO 授权规则。图片准入不在本提案内。

第 2–9 次调用累计重复发送了 660,449 个工具结果字符，而工具最初仅产生 127,098 字符。对记录的结果大小设想 `glob`/`grep` **完整结果最多 4,000 字符**，且没有额外翻页或输出变化，则六条结果受影响：五条 `glob`、一条 `grep`。首次传给模型时减少 59,769 字符，后续重复减少 305,357 字符，共 365,126 字符。按每四字符一 token 的代理值，分别约为 14,942 首次输入及 76,339 重复输入 token。若首次传输未命中缓存、后续重复均命中，按当前非高峰费率，毛价格等值约少 **USD 0.01154**（该子会话 USD 0.09173 的 12.58%）；其中重复的缓存文本仅贡献约 USD 0.00168。这是明确假设的情景，而非实测 provider 用量或保证的账单降幅：截断标记占空间、可能翻页、分词和缓存命中可能不同，模型输出也可能变化。

## Alternatives considered

**主动裁剪历史并允许回取。** 所测子会话没有发生裁剪，而缓存读取仅占价格等值的 9.23%。已记录的 `compaction/prune` 配合有界回取能保留原结果，但改变较早前缀可能使便宜的缓存命中变成昂贵的未命中。这是默认关闭的可选实验；只有在可比的公开仓库真实模型运行中，计入失去的命中、回取调用和输出变化后总价格仍更低，才可启用。

**只依赖缓存命中。** 实测 85.1% 的缓存读取占比已有价值，但无法控制新的非缓存搜索输出或上下文压力。在来源处限制结果既保留既有前缀模式，也缩小首次传输；实际价格和证据覆盖仍须在真实模型上比较。

**为 Detective 选择更便宜的模型。** [#35](https://github.com/Biyocon/biyocon-harness/issues/35)在 #30 之后负责按角色选择 provider/模型。较便宜的模型可能降低货币成本而不减少 token，也可能削弱证据选择或结构化输出质量。须待角色路由及凭据得到支持后再比较；#58 不应写死模型。

**只限制输出、总 token 或捕获文件数。** 限制可以终止运行或拒绝证据，却不能降低完整答案的成本。阶段 B 保留安全上限和明确的不完整状态，但不将其宣称为阶段 A 的节省。

## Acceptance criteria

- 阶段 A 不改变 v5 运行记录或现有会话事件格式。聚焦测试和经真实可运行示例生成的无密钥 snapshot 覆盖仅限 Detective 的字符上限、准确的截断标记与数量、稳定游标页面及冷恢复、缺少保存结果时的失败、后段不利发现、索引排序、哈希验证的捕获读取，以及对未检查范围作限定的论断。批评者和 Auditor 保留现有完整依据；分析仍为只读。其他角色继续使用原有工具上限。
- 使用相似规模的公开合成仓库、真实模型及 process-env 凭据，对照基线与来源处限额的阶段 A：provider 报告的非缓存/缓存输入、输出/推理、总提示 token、**价格等值及可取得的实际账单费用**、延迟、后续页面及已接受的证据覆盖。包含所有来源均重要、节省消失的案例。不得公开私人会话数据。主动裁剪单独评估；只有计入缓存命中变化后总价格更低才启用。
- 阶段 B 验证加载时的配置、重放时保留的额度和覆盖、用量缺失、单次超额、返工/恢复共用额度及终态不完整呈现。若运行/会话事件改变，增加所需无密钥 transcript 并更新两个 SDK 投影。与 #30 第二阶段协调记录版本和清单。

## Risks

来源处限额可能增加翻页调用；若截断不明确、页面不稳定或检查不完整时未缩小最终论断，也可能隐藏关键结果。保存的完整搜索结果可能过大或不可用；分页须明显失败，不能暗示已全面检查。主动替换 surface 的价格收益尚未得到证明，因为它可能破坏可复用的缓存前缀。索引不会发现未引用的工作区文件；没有 #30 的清单，发现覆盖仍属临时。保守预检可能阻止有用工作，而 provider 仍可能在单次调用中超额。避免引入与 #30 冲突的独立 v6。
