# Agent Note: 限制 Detective 的证据读取与 token 用量

Status: proposed

[English](2026-11-05-conductor-detective-evidence-budget.md) | 中文

## Problem

[Issue #58](https://github.com/Biyocon/biyocon-harness/issues/58)记录了所有者报告的一次大型目录分析：Detective 约使用 472,000 token。私人运行没有重放，因此无法确定费用分别来自重复提示、仓库读取、模型输出或返工。费用必须可预测，未检查的来源不能被表述为已审阅，也不能削弱批评者和 Auditor 可用的证据。

在 `b230cf38ac` 上，[准入捕获](../../../../packages/conductor/tool-conductor/src/materials.ts)保存完整的当前请求及明确引用的文本文件；默认上限为 16 个文件、每份输入 65,536 字节及序列化准入记录 262,144 字节。[Detective 分派](../../../../packages/conductor/tool-conductor/src/index.ts)将完整 `admission` 连同所有文件的 `content` 放入 JSON 提示。子会话还收到 Detective 和共享 specialist skill（技能）、结构化输出 schema，以及读取/搜索工具（`read`、`read_image`、`grep`、`glob`）；后续模型请求可能包含已记录的读取结果。当前生产者路径没有 Detective 专用的输入或累计 token 上限。[批评者](../../../../packages/conductor/tool-conductor/src/analysis-dispatch.ts)则接收与候选报告绑定的摘录，并有逐次尝试及逐运行记录的 token 上限。

## Proposal

在持久运行记录中保留完整且经哈希验证的准入内容。分派 Detective 时，提供完整的当前请求及所有已捕获文件的确定性索引：selector、material ID、哈希、字节数、行数和明确的 `not inspected` 状态。初始提示不再重复文件正文；一个只读、限定于该子会话的工具按需从不可变捕获内容返回行范围。工具验证准入哈希，在子会话记录准确的请求范围与返回文本，拒绝未知 ID 和超预算请求，且不会把已变化的工作区文件重新读取为准入材料。其 UI 渲染意图为 `generic`，`locations` 指向准确的来源 selector 与行范围，且只由工具参数决定。通用工作区读取/搜索工具仍只读，用于发现文件；其返回文本与 token 费用计入同一 Detective 预算。模型断言不能让已发现但未捕获的文件获得准入 material ID 或引用资格。

为每次 Detective 尝试记录宿主拥有的覆盖台账：每份准入材料的检查状态（`read`、`summarized` 或 `not inspected`）、实际读取范围、选择理由及遗漏的字节/行数；另行记录发现的工作区路径及可取得的版本或摘要。摘要只帮助定位，不能作为未观察到的论断的证据。选择可优先考虑所有者引用的来源与问题匹配项，但完整索引始终可见，每项排除均明确记录。如果剩余预算无法读取相关来源，Detective 返回有界的不完整结果，列出遗漏的 selector 及受影响的结论；Conductor 不得将其变成全面的 `ready` 报告，也不得将其作为完整候选交给批评者。所有者后续答复可以批准新运行或缩小问题，不能将未审阅的证据改称已审阅。

新增经验证的部署上限：Detective 每次模型请求的预估输入、每个子会话包含推理的输出，以及每次运行由 provider 报告的 Detective token 总量。准入时保存上限；每次子会话和模型请求之前预留，并对输入、缓存读取/写入、输出和推理计数，避免重复计数。请求预检包含 persona、工具 schema、系统段落、完整已记录历史及下一份输入；排除工具的字节或 token 估算不足以约束请求。无法提供可靠预检上限或可执行输出上限的 provider 路径在分派前失败。每次调用后计入报告用量；缺失或无效的用量按预留额度收费并阻止再次调用。provider 的实际超额会终止运行并明确披露；预检无法追溯阻止单次调用超额。返工或所有者恢复后创建的新子会话共用保留的运行预算。达到上限时持久记录已消耗/已预留/上限、已检查与遗漏材料，以及终态 `incomplete`；不得通过自动返工循环暗中重置额度。

Detective 继续只读地澄清范围。生产者引用的 `material_spans` 仍绑定完整准入捕获。[批评者的摘录验证](../../../../packages/conductor/conductor/src/analysis-materials.ts)及必经批评不变。Auditor 保留同样的完整准入材料，必须拒绝缺乏支持或不完整的事实论断；本设计不通过减少其证据来节省 Auditor 的 token。Gate C、实施批准和 GO 权限不变。图片准入仍不受支持。

## Measurement and expected savings

以下是 `b230cf38ac` 上的源码级测量，不是模型运行。内存脚本使用 `captureIntakeMaterial`、`admitIntake`、`createRun` 及从 master 转译的原始 `composeSpecialistPrompt` 函数。输入为简短的合成请求以及 0、1 或 16 个明确引用、各有 12,000 字符的 ASCII 文件；16 文件的序列化捕获为 199,854 字节，低于默认上限。提示、skill 正文和 schema 长度均按批评者预检使用的每四字符一 token 代理值计算。没有使用私人文件或 provider 凭据。

| 引用文件 | Detective 提示字符数 | 提示 token 代理值 | 捕获内容贡献（含当前请求） | 初始提示 + Detective/共享 skill + 输出 schema 的代理值 |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 2,790 | 698 | 16 | 3,180 |
| 1 × 12,000 | 15,406 | 3,852 | 3,079 | 6,334 |
| 16 × 12,000 | 204,640 | 51,160 | 49,020 | 53,642 |

这 16 个文件的拟议索引约有 4,505 字符，即 1,127 个代理 token。若 Detective 需要完整读取其中四个文件，其 48,000 字符约增加 12,000 个代理 token：首次请求的材料部分由约 49,020 降至约 13,127，毛减少约 35,900（73%）。若子会话发出八次请求，并且保留所有已读取文本，示例毛差约 287,000 个代理 token；工具包装、历史增长、provider 分词、缓存与后续读取都会改变此数。读取全部 16 个文件会消除大部分节省。所有者报告的 472,000 token 无法用此合成测试分解，也不是已验证基线。

## Durable format and coordination

新增的保留预算字段、覆盖状态和终态不完整语义会改变经验证的 Conductor 运行记录。不得让 `CONDUCTOR_RECORD_FORMAT_VERSION = 5` 获得新含义；实现需要下一个单调递增的格式版本。[Issue #30 第二阶段](https://github.com/Biyocon/biyocon-harness/issues/30)也需要 v6，涉及 Auditor 入口、verification、未提交文件摘要及 Git 之外的文件清单。在实施任一 issue 前，应决定统一的 v6 记录与清单归属。若 #30 先发布 v6，#58 使用再下一个版本，不能复用 v6。第二阶段清单应提供新发现文件的稳定路径/版本来源；在此之前，工作区发现项明确保持临时状态，不能暗中变为准入材料。

## Alternatives considered

**仅降低 `maxMaterialFiles` 或 `maxMaterialBytes`。** 这会在 Detective 识别相关证据之前拒绝或遗漏来源，也不能处理重复的工作区读取。现有准入上限保留为安全上限，而非费用设计。

**在 Detective 之前汇总全部文件。** 摘要可能抹去关键反证，并产生未经验证的第二份分析。拟议索引和按需准确行范围保留原文，并标明未读部分。

**只限制 Detective 输出或缩短最终报告。** 本例测得的初始输入和重复读取历史是主要成本；简短答案本身不能限制输入费用或证明覆盖范围。

**原样复用批评者仅含摘录的提示。** 批评者评估已有行范围的完整候选报告。Detective 必须发现范围并决定检查哪些证据，因此需要完整来源索引与受控读取，而不能只看生产者选出的摘录。

## Acceptance criteria

- 使用公开的合成小型和大型仓库，对现有与拟议路径的初始调用、重复读取、返工和恢复进行比较，分别记录 provider 报告的输入、缓存、输出和推理用量；公开来源哈希、测量及限制，不包含私人数据。纳入所有文件均重要、节省消失的案例。
- 在索引靠后的文件放置相关发现，并在未选文件放置不利发现。两者须可追溯到准确的 material ID 和行，或者结果明确为不完整；全面且被接受的报告不能隐藏遗漏来源。批评者和 Auditor 保留现有批评与引用检查。
- 单元测试和经真实可运行示例生成的无密钥 snapshot 覆盖索引排序、不可变范围读取、已变化或未知材料拒绝、零/部分/完整覆盖、预检拒绝、用量缺失、单次超额、跨返工/恢复的总额耗尽，以及终态不完整呈现。若运行/会话事件发生变化，同时更新两个 SDK 投影。
- 加载时验证配置，重放时验证已持久化上限和台账。确认分析始终只读，即使所有者答复后也不能获得实施批准或 GO。

## Risks

索引仍可能漏掉未引用的工作区文件；在与 #30 协调的清单可用之前，结果必须说明发现不完整。保守预检可能过早终止有用分析，而 provider 仍可能在单次调用中超额；报告必须披露两种情况。快照读取增加工具开销和延迟，读取所有来源可能使用与当前路径相同甚至更多 token。未经 #30 协调单独引入 v6 会造成可避免的格式反复。
