# Agent Note: Detective 的证据与重复历史成本

Status: proposed

[English](2026-11-05-conductor-detective-evidence-budget.md) | 中文

## Problem

[Issue #58](https://github.com/Biyocon/biyocon-harness/issues/58)报告 Detective 分析大型目录时约用了 472,000 token。下方经所有者批准的本地测量表明，重复发送的对话历史和工具结果是该次运行的主要优化机会。单纯设限只会提前终止分析；有效节省必须减少冗余输入，同时明确标示未检查的来源，并保留批评者与 Auditor 的证据。

当前的[分派](../../../../packages/conductor/tool-conductor/src/index.ts)会把完整的 v5 `admission`（包括已捕获文件正文）放入 Detective 提示。子会话也可用 `glob`、`grep` 和 `read` 发现工作区文件。后续每次模型请求都会从会话重建完整的模型可见历史；现有[工具结果裁剪器](../../../../packages/compaction/compaction-tool-result-pruner/src/index.ts)仅在上下文压力或溢出触发压缩时运行。所测子会话没有裁剪事件。[批评者](../../../../packages/conductor/tool-conductor/src/analysis-dispatch.ts)接收绑定候选报告的摘录，且拥有独立的实测预算；本提案不削减其输入或 Auditor 的访问能力。

## Proposal

### 阶段 A：不改变 v5 运行记录，减少重复输入

在 v5 记录中保留完整且经哈希验证的[准入捕获](../../../../packages/conductor/conductor/src/types.ts)。分派 Detective 时，从已有的 `id`、`selector`、`sha256` 和 `content` 派生已捕获文件的有序索引；字节数和行数现算，不增加记录字段。初始提示发送当前请求和索引，不发送文件正文。限定于该子会话的只读工具从准确的捕获 `content` 返回有界的行范围，验证哈希，并通过现有工具调用/结果事件记录参数和返回文本；它绝不以变化后的工作区文件代替准入内容。UI 渲染意图为 `generic`，`locations` 仅根据参数指向准确的 selector 和行号。未知 ID 或过大的范围明确报错。

同一阶段单独处理实测的历史成本：Detective 完成一步后，主动用小型、明确的省略标记替换模型可见会话中选定的较早大体积工具结果，沿用现有已记录的 `compaction/prune` 和 `tool/result` surface 替换机制。原结果留在只追加的子会话日志中。限定于该子会话的只读回取工具可通过稳定事件身份返回原结果的有界范围；回取本身也记入日志和用量。不得拆开工具调用与结果、不得在模型首次看到当前步骤结果前裁剪，也不得让缩短后的文本成为证据唯一副本。部署可配置的确定性保留规则决定可裁剪的年龄与大小，不能在插件中写死。保留引用所需的来源身份和行号。摘要或标记只用于定位，不能证明被省略的内容。

阶段 A 沿用现有会话事件类型，v5 `ConductorRun` 字段不变。新工具只对 Detective 子会话和所属准入运行开放；普通工作区读取继续只读。工具返回的工作区发现项不会因此获得准入 material ID 或引用资格。完整捕获继续供批评者验证摘录和 Auditor 检查。报告必须披露未检查的材料；阶段 A 不声称已有宿主拥有的持久覆盖台账或新终态。

### 阶段 B：v6 用量核算与明确的不完整终态

为每次 Detective 尝试增加宿主拥有的覆盖台账：准入材料的检查情况及准确范围、已发现工作区来源及可取得的版本或摘要、选择原因，以及影响结论的遗漏。只有准确的来源片段算作已检查证据。准入时保存经验证的每请求输入、包含推理的输出以及每运行总 token 上限。预检包含 persona、系统文本、工具 schema、下一份输入及已记录的模型可见历史；把 provider 报告的非缓存输入、缓存读取/写入和输出作为互不重叠的计数，推理包含在输出中。用量缺失或无效时消耗预留额度并阻止下一次调用；provider 超额则终止运行并披露。返工和所有者继续执行共用保留的运行额度。

如果剩余额度不足以检查相关证据，记录已消耗/已预留/上限和遗漏范围，以终态 `incomplete` 结束。不得把它作为完整候选交给批评者、暗中重置额度，或转换成全面的 `ready` 报告。这是有界的失败状态，不是效率收益。

这些新增的运行字段和终态语义需要新的记录版本。与 [#30 第二阶段](https://github.com/Biyocon/biyocon-harness/issues/30)协调统一的 v6 归属和 schema；该阶段还计划 Auditor 入口、verification、未提交文件摘要及 Git 外文件清单。若 #30 先交付 v6，阶段 B 使用下一个版本。#30 清单可为新发现的文件提供稳定来源；在它出现之前，发现项仍属临时材料。

两个阶段均保留只读分析、生产者依据完整准入捕获填写的 `material_spans`、必经批评、Auditor 可用的全部证据，以及既有 Gate C/GO 授权规则。图片准入不在本提案内。

第 2–9 次调用累计重复发送了 660,449 个工具结果字符，而工具最初仅产生 127,098 字符。v5 捕获只有一条 99 字符的当前请求，**没有捕获文件**。因此，阶段 A 的捕获索引部分对本次运行预计节省约 **零** token。历史部分若在每个已完成步骤后按现有 8,192 字符阈值、4,096 字符开头及 1,024 字符结尾主动裁剪，则七条结果会被处理；若均无需回取，可少重复发送 338,328 字符，即约 84,582 个毛输入 token 代理值（报告输入的 18.7%）。这不是实测 provider 用量或净价格预测：回取、新工具封装、分词方式及缓存命中损失都可能减少甚至逆转收益。阶段 A 的验收必须在可比的公开实模型运行中同时测量总提示 token 与实际计费成本。阶段 B 本身对完成的分析预计**不节省 token**；限制只会停止后续调用，且必须披露不完整状态。

## Alternatives considered

**仅在上下文压力时裁剪。** 所测子会话没有发生裁剪，但仍重复发送 660,449 个工具结果字符。在后续 Detective 请求前触发确定性的可回取裁剪能更早处理费用，但必须衡量缓存失效及回取次数。

**压缩或删除旧工具结果而不给回取途径。** 这可能丢失不利证据。已记录的 surface 替换和有界回取让原文留在会话日志中，并向模型标示省略；无法取回所需片段时，答案必须缩小范围。

**只依赖缓存命中。** 实测 85.1% 的缓存读取占比可能降低价格，却不减少 token 用量或上下文压力。改写较早前缀可能将命中变成未命中，因此须分别测量净价格和延迟。

**为 Detective 选择更便宜的模型。** [#35](https://github.com/Biyocon/biyocon-harness/issues/35)在 #30 之后负责按角色选择 provider/模型。较便宜的模型可能降低货币成本而不减少 token，也可能削弱证据选择或结构化输出质量。须待角色路由及凭据得到支持后再比较；#58 不应写死模型。

**只限制输出、总 token 或捕获文件数。** 限制可以终止运行或拒绝证据，却不能降低完整答案的成本。阶段 B 保留安全上限和明确的不完整状态，但不将其宣称为阶段 A 的节省。

## Acceptance criteria

- 阶段 A 不改变 v5 运行记录或现有会话事件格式。经真实可运行示例生成的无密钥 snapshot 和聚焦测试覆盖索引排序、哈希验证的捕获读取、有界且已记录的回取、确定性主动裁剪、重放，以及可重新读取或促使报告限定范围的后段不利发现。批评者和 Auditor 继续获得现有完整依据；分析仍为只读。
- 使用相似规模的公开合成仓库、真实模型及 process-env 凭据，对照基线与阶段 A 的 provider 报告：非缓存/缓存输入、输出/推理、总提示 token、计费价格、延迟、回取频次及已接受的证据覆盖。包含所有来源均重要、节省消失的案例。不得公开私人会话数据。
- 阶段 B 验证加载时的配置、重放时保留的额度和覆盖、用量缺失、单次超额、返工/恢复共用额度及终态不完整呈现。若运行/会话事件改变，增加所需无密钥 transcript 并更新两个 SDK 投影。与 #30 第二阶段协调记录版本和清单。

## Risks

主动替换 surface 可能破坏可复用的缓存前缀，回取也可能加入比裁剪节省更多的文本。若准确的原结果不可访问，标记可能隐藏关键证据；检查不完整时必须缩小最终论断。索引不会发现未引用的工作区文件；没有 #30 的清单，发现覆盖仍属临时。保守预检可能阻止有用工作，而 provider 仍可能在单次调用中超额。避免引入与 #30 冲突的独立 v6。
