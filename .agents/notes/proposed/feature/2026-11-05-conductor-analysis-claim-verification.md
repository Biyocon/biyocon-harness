# Agent Note: Evidence-bound claims in Conductor analysis

Status: proposed

English | [中文](2026-11-05-conductor-analysis-claim-verification.zh.md)

## Problem

[Issue #75](https://github.com/Biyocon/biyocon-harness/issues/75) reports a read-only analysis in which Detective and Auditor repeatedly attempted unavailable `web_search` calls, then Auditor described unverified facts as correct and Arbiter accepted the report. The observation establishes a verification gap, not that the reported facts were false. The [analysis critic](../../implemented/feature/2026-10-28-conductor-analysis-critic.md) challenges reasoning and explicitly leaves factual and citation checks to Auditor; its `holds` verdict cannot certify those facts.

The present [Auditor role](../../../conductor/roles/05-auditor.md) asks for an assessment of the candidate and its sources without a claim-level verification result. [AnalysisEnvelope](../../../../packages/conductor/conductor/src/types.ts), [ReportDecision](../../../../packages/conductor/conductor/src/types.ts), and their [validation](../../../../packages/conductor/conductor/src/analysis.ts) bind candidate and audit hashes, but do not require a source-backed status for each factual claim. `evidence_reviewed: string[]` is not a proof that the reviewed source supports the accepted claim.

## Proposal

### Explain and remove the unavailable-tool instruction

The source of the `web_search` suggestion is identifiable without private run data. The [base bundle](../../../../packages/bundle/base/cordis.patch.yml) mounts `tool-web` for every mode. Its [search plugin](../../../../packages/web/tool-web/src/search.ts) registers both the tool and an unconditional `tool:web_search` system-prompt section telling the model to use it. [Child composition](../../../../packages/subagent/subagent/src/child-agent.ts) inherits parent prompt sections and then restricts tools. [Conductor's analysis filter](../../../../packages/conductor/tool-conductor/src/workflow-child.ts) exposes only `read`, `read_image`, `grep`, and `glob`, while its [dispatch prompt](../../../../packages/conductor/tool-conductor/src/index.ts) lists `read` as an allowed action. A search of the Conductor role, specialist skill, and dispatch text found no `web_search` instruction. The inherited system text is therefore a concrete conflicting instruction; model behavior may contribute, but need not be invoked as the sole explanation.

Phase 1 is a general subagent-composition fix, delivered in its own PR without changing the Conductor record or session format. Extend `PromptSection` with a typed optional `requiresTools` list: a section is included only when every named tool belongs to the current scope's effective tool view. This metadata is explicit; never parse the `tool:` name prefix. Unassociated sections retain their existing behavior. Validate non-empty, unique names against registered capabilities during assembly, after registration has completed; a known but filtered tool suppresses its section. A tool provider supplies the effective capability names separately from wire schemas, since Code Mode may expose only `run_code` while retaining callable capabilities. Recompute visibility on every assembly and cold resume, preserving parent/sibling isolation and scoped shadowing. Omit a suppressed section before evaluating its text provider. Search guidance belongs to `web_search`; any follow-up sentence recommending `web_fetch` requires both tools. Executor restrictions remain authoritative, and the resulting prompt uses existing logged snapshots.

This partially supersedes only the unconditional standalone-guidance policy in [subagent composition](../../implemented/feature/2026-07-12-subagent-persona-tool-filter-and-depth.md); its persona, filtering, depth and provider decisions remain active. The generic association is realized by [tool-associated prompt sections](../../implemented/feature/2026-11-11-tool-associated-prompt-sections.md); the later Conductor-specific changes below remain proposed.

Affected packages are [system-prompt](../../../../packages/core/system-prompt/src/index.ts) (typed association and assembly), [tools](../../../../packages/core/tools/src/index.ts) (effective capability-name projection), and [tool-web](../../../../packages/web/tool-web/src/search.ts) (search/fetch declarations). Subagent composition uses these generic facilities; Conductor requires no special suppression rule. Tests cover system-prompt scoped assembly, missing/filtered capabilities, parent/sibling isolation, shadowing, provider invocation and unchanged unassociated sections; tools tests cover native/code/both modes; tool-web tests cover search-only and mixed availability. The subagent driver's preset-inheritance tests and continuation-inheritance tests exercise fresh children and cold resume. Add an assembled keyless transcript with restricted and unrestricted children. Update owning README/JSDoc and system-prompt type projections in that implementation PR.

The later Conductor-specific phase adds the exact available tools and no external retrieval to specialist input. A validated positive-safe-integer Config limit counts all unavailable-tool denials per child attempt, across tool names and arguments; propose a default of two (one logged correction, then visible failure). Persist the count across continuation/resume; reaching the limit terminates the attempt without automatic retry. This does not widen access.

### Require a claim-level audit before documented acceptance

Recommend a claim list rather than a complete text partition. Each claim has a stable ID, a non-empty exact quote from the candidate, and an occurrence index when the quote repeats. The host checks substring identity without normalization, valid occurrence, unique IDs and candidate hash. Auditor checks the entire candidate independently for omitted claims and materiality; a list entry is not proof of completeness. If it finds an omission or a materiality downgrade hiding an unsupported conclusion, it returns rework. Each assessment is `source_verified` with an admitted source ID and exact lines supporting the proposition, `derived` with verified premise IDs and an explicit inference, or `unverified` with missing evidence. Validate source hashes and ranges, complete assessment coverage of the submitted claim IDs, acyclic supported premises, and audit identity. The host rejects `current-request` as factual support, directly or through derived premises, in either mode; it defines scope and owner assumptions, not corroboration. Model memory, a URL alone, and discovered but unadmitted files cannot become source verification. Source support and semantic completeness remain Auditor judgments, not guarantees provided by substring validation.

Trusted specialist instructions delimit candidate and source text as untrusted evidence, never instructions. Embedded directives cannot authorize tools, select evidence mode or override acceptance predicates. Auditor independently checks claims and Arbiter reviews the audit rather than obeying report instructions; these measures reduce injection risk without guaranteeing semantic immunity.

Two host-selected evidence modes apply. `model_knowledge` means admission contains no source material beyond the obligatory `current-request`; the request states the question and is not independent corroboration. Arbiter may accept such an answer, including material unverified claims, if the analysis otherwise satisfies its criteria. Its whole report must carry the host-rendered label **“Bygger på modelviden, ikke verificeret mod kilder” / “Based on model knowledge, not source-verified”** in DA/EN, including the final response and exported/displayed report. It must never be described as documented or factually verified. The logged parent result must preserve that label rather than relying only on a model paraphrase. Neither producer nor Arbiter may select this mode to avoid checking existing sources. In this mode all analysis children, including Auditor and Arbiter, expose only the required structured-output tool: child filtering and execution guards deny file/image reads, discovery, web access and other source retrieval. Suppress workspace/source-content injection while retaining trusted role instructions and the request. Source access requires a new authorized intake, never an implicit mode change.

When any source material is admitted, `source_backed` applies even if those sources are insufficient or irrelevant. The host rejects `accept` if any claim material to a conclusion is unverified; materiality is independently assessed by Auditor. Accepted incidental unverified claims cannot support conclusions. The host renders “Unverified / Ikke verificeret” at each such claim occurrence and binds the presentation to candidate/audit hashes; acceptance fails closed if any required label is missing or attached to the wrong occurrence. Every accepted display/export/final response preserves this labelled presentation. Use `revise` when admitted evidence, removing a claim, or narrowing a conclusion can repair the report; use `blocked` when essential verification requires inaccessible sources or actions outside the mandate. New evidence requires a new authorized intake, never a silent change to the capture. Arbiter receives the exact candidate, critic challenge, audit and assessments; acceptance describes only the verified scope in source-backed mode.

Persist the claim inventory, assessment, host-selected evidence mode, and acceptance condition in the Conductor run, with hashes tied to the exact candidate and audit. These required fields and terminal semantics need the next monotonic record version; do not reinterpret v5. Coordinate the version with [#30 phase 2](https://github.com/Biyocon/biyocon-harness/issues/30) and [#58 phase B](2026-11-05-conductor-detective-evidence-budget.md). Before implementation, the owner assigns one schema/version owner across all three workstreams. That owner serializes a coordinated schema allocation against merged master: one version has one layout, never parallel incompatible v6 definitions. If v6 has shipped, the owner assigns the next version after checking the merged schema; verify that allocation again before merge. No compatibility migration is implied. All model-visible instructions, source excerpts, tool-denial feedback, and returned classifications must be reconstructable from the session log. The seven roles, mandatory critic, read-only analysis, and Gate C/GO authority remain as defined by the existing Conductor route.

## Alternatives considered

**Prompt-only warning.** It may reduce unsupported tool calls, but a model can still assert that an uncited fact is correct; typed claim results and a host acceptance rule are necessary.

**Full non-overlapping content partition versus exact-quote list.** A partition can mechanically prove that every character was assigned to a segment, but cannot prove that a segment marked non-factual contains no facts. It requires offset precision and extra segments for headings and connective prose. Quotes tolerate unrelated layout changes better, but duplicate text needs an occurrence index and omitted claims still require independent audit. Any candidate change invalidates either form's audit. Recommend the quote list for lower structural burden, retaining Auditor's whole-report omission check.

For an illustrative 2,000-token report with 20 claims, estimate partition metadata at 40 segments × 20–30 tokens = 800–1,200 extra producer-output tokens; quotes at 20 claims × (20 quoted tokens + 6–10 metadata tokens) = 520–600. Both add roughly 400–800 audit-output tokens for assessments. These are planning estimates, not measured tokenizer or billing results; repeated transmission to critic, Auditor and Arbiter adds input cost. Long quotes can reverse the saving. Measure actual input/cache/output usage and retries on public material before implementation acceptance; neither variant needs an extra extraction-model call by design.

**Block every unverified report.** Rejected for source-free knowledge questions under the owner's decision. Explicit whole-report model-knowledge labelling permits useful answers without claiming verification; admitted-source analyses keep the strict material-claim rule.

**Enable web search for analysis.** It would expand the read-only role's external access, introduce new source provenance and cost, and still not establish that a returned page supports each claim. External retrieval needs its own authorization and admission design.

## Acceptance criteria

Phase 1 tests the generic typed association, including arbitrary section names with no `tool:` prefix, hidden tools with registered names, unavailable `web_fetch` follow-ups, Code Mode, scoped isolation, fresh/cold children, and unchanged logging formats. Its own implementation PR includes a keyless assembled subagent transcript.

Phase 2 adds `conductor-installed` keyless snapshots for a mixed source-backed report, one denied tool call and bounded repeated-denial handling, Auditor omission detection, and Arbiter revise/blocked outcomes. A source-free knowledge question must be accepted with the exact whole-report EN/DA label; the required current request alone must not force source-backed mode. A report with admitted but irrelevant sources cannot downgrade itself to model knowledge. Tests reject unmatched/ambiguous quotes, missing assessments, forged sources/ranges, cyclic derivations, stale hashes, mode tampering, and source-backed acceptance of material unverified claims. Adversarial cases include source/report instructions to fabricate verification or change mode, request assertions plus an irrelevant admitted file, direct/derived request corroboration, source access in model-knowledge mode, alternating denied tool names/arguments across resume, and absent/misplaced incidental labels. Host predicates reject invalid decisions regardless of embedded instructions; public model tests also measure semantic injection failures. UI/final-result checks preserve textual labels on reload and on the final parent response, independent of colour. Replay reproduces mode, classifications and hashes; update both SDK projections where affected. Public real-model comparisons measure tokens, cache usage, calls, retries and omission detection for both inventory alternatives. No private run data enters fixtures or logs.

## Risks

Claim inventories and independent review add tokens and may still miss a factual assertion or misjudge source support; the design does not claim formal proof of semantic truth. Strict blocking can reduce completed reports when admitted sources are sparse. Suppressing tool guidance must follow the effective scoped tool view, or it can hide a tool that another role legitimately has. Cross-process concurrency remains governed by [#51](https://github.com/Biyocon/biyocon-harness/issues/51).
