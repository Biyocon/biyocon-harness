# Agent Note: 通过持久化的所有者问题恢复 Conductor 升级处理

Status: proposed

[English](2026-10-30-conductor-owner-escalation-resumption.md) | 中文

## 问题

[Issue #37](https://github.com/Biyocon/biyocon-harness/issues/37) 描述了运行 CON-2026-4272：Strategist 请求修改六个文件的权限，并要求澄清两个计划选择，但 Gate B 直接升级处理，没有向所有者提问。另起一次运行会丢失问题、专家证据和所有者回答之间的关联。

在 master b0d5825b6fa17e9ffb395e2996e16a4a00f34ca2 上，[恢复校验](../../../../packages/conductor/conductor/src/persistence.ts) 拒绝恢复已升级的运行，[入口历史校验](../../../../packages/conductor/conductor/src/intake-history.ts) 也将升级视为终态。[派发校验](../../../../packages/conductor/conductor/src/drive.ts) 还把合理的权限请求与完整性故障归为一类。如果允许恢复所有升级情况，就会让所有者回答豁免本来必须坚持的检查。

[Gate C](../../../../packages/conductor/tool-conductor/src/index.ts) 已通过宿主取得针对精确执行基线的批准。[ApprovalService](../../../../packages/interaction/user-approval/src/index.ts) 不提供自由文本回答，而 [UserQuestionService](../../../../packages/interaction/user-questions/src/index.ts) 虽然支持提问，却不会持久化 Conductor 的继续执行状态。[API 代理](../../../../packages/host/apiproxy/src/api-proxy.ts) 将待处理请求保存在内存中，因此浏览器重连与宿主重启需要不同的恢复机制。

## 提案

将可恢复的升级保存为持久化的所有者问题，再通过 Conductor 专属的宿主控制器恢复同一次运行。复用现有问题传输和根代理身份检查，并增加类型化的 Conductor 交互；Gate C 的批准服务保持独立。P1 交付下述记录与校验器基础；生产交互仍作为 P2/P3 提案。

七个专家角色及其职责保持不变。所有者提供决定和澄清，而不是新的专家报告或 gate 通过结论。实施和分析保留现有路线；本功能不增加入口、分析批评、提供商、领域代理或文档格式。

### 实施阶段

P1 已交付记录 v4 的领域基础：只追加的所有者台账、精确子会话与报告来源、经验证的授权变更和逐门禁重新评估上限，以及分析和实现的严格重建。Conductor 子会话写入校验即使在宽泛工作区授权下也拒绝 Git 元数据，包括规范化别名路径。它仍仅供测试提供者使用：现有 required-on-read `conductor/checkpoint` 事件携带完整台账，不启用新会话事件类型、真实回答控制器、恢复轮次、路由钩子或 UI。专用交互事件及 SDK 事件扩展属于 P2。通过已安装预设的 keyless 场景验证脚本化接受、拒绝与提供者不可用时的停放。完整交互由 P3 交付前，本说明有意保持 proposed。现有版本 3 运行被拒绝，升级后无法恢复。

按以下顺序，以三个连续 PR 实施 #37。每个 PR 完成后均停止，等待所有者和 Claude 评审；设计或前一阶段获批，不代表授权下一阶段或合并。

| 阶段 | 范围 | 验证与评审停止点 |
|---|---|---|
| P1 | 记录 v4、所有者交互台账、升级分类和校验器，包括每个 gate 的所有者重新评估上限。 | 使用脚本化宿主回答测试受理、回答、计数上限和持久化；进入 P2 前停止等待评审。 |
| P2 | Conductor 专属宿主控制器、持久化回答与恢复回合，以及路由守卫。 | 测试同一运行继续执行、崩溃和取消边界、失效回答及主代理工具禁用；进入 P3 前停止等待评审。 |
| P3 | EN/DA 类型化所有者问题卡片、无障碍控件、浏览器 e2e 和 GIF。 | 通过应用验证真实交互；从端口 3090 的 PR 服务器录制 GIF 并发布到独立 assets 分支；停止等待评审。 |

每个阶段都必须独立安全。不得启用尚未完成的生产交互路径：前期由脚本化测试提供方覆盖，生产交互提供方不可用时，运行必须保持暂停，不授予任何权限。停放和所有者拒绝的结果保留原始升级原因。面向用户的回答功能不可用消息说明此限制，但不提实现阶段名称。

### 升级分类与阶段转换

创建问题之前，先区分可恢复的所有者输入与终止性故障。仅明确的澄清请求、具体的权限修订提案，以及已耗尽预算但可恢复的返工路线可以提问。运行身份错误、路由被篡改、未经授权的执行、基线篡改、沙箱违规或 Gate C 批准被拒绝，仍然必须终止。普通异常绝不能转化为可批准的问题。

对于分析，应增加专门的只读澄清请求，而不是整体接纳实施流程的 change_requests：[分析信封](../../../../packages/conductor/conductor/src/analysis.ts) 目前拒绝这些字段。拒绝把分析变为实施、授予写权限或取得执行授权的请求。

| 条件 | 拟议的持久化转换 | 下一步 |
|---|---|---|
| gate X 出现可恢复的升级 | running/rework → awaiting_owner | 保留 X 的升级记录；持久化后展示问题。 |
| 有效回答或具体提案获得批准 | awaiting_owner → 等待继续执行 | 记录回答和经校验的恢复计划；重新评估受影响的 gate。 |
| 所有者拒绝 | awaiting_owner → aborted | 记录所有者拒绝；不再派发专家。 |
| 关闭对话框、客户端断开或没有可用的交互提供方 | 保持 awaiting_owner | 如实报告等待或不可用；不授予任何权限。 |
| 完整性或安全违规 | 终止于 escalated | 说明故障；不提供继续执行操作。 |
| 所有者重新评估额度耗尽 | 终止于 escalated | 报告 gate、已用次数、上限和未解决原因；不再允许恢复。 |

Gate 历史只能追加。重新评估增加新的 gate 结果和新的子代理尝试，绝不将原升级改成 pass。普通澄清会在原 gate 恢复原角色。如果权限修订使计划或基线失效，恢复计划必须先经过 Strategist 和 Devil's Advocate，再允许任何后续实施；原升级仍关联到这条修复路线。

### 所有者操作与权限

应用提供本地化标签 Godkend、Afvis 和 Svar og fortsæt，背后的机器操作为 approve、reject 和 answer_continue。翻译后的标签和自由文本绝不能决定权限。一个问题使用稳定的条目 ID 组合所有必答澄清项；宿主原子地接收一次完整回答，而不是把部分回答当作隐含批准。

只有宿主能够校验的具体提案，在展示完整预览后才可使用 Approve。回答并继续要求每个必答项均有回答，文本非空且长度受限，选项 ID 有效。如果同时需要澄清和权限修订，回答必须包含澄清内容以及对所展示修订的明确确认。默认选中、关闭对话框或跳过必答问题都不构成同意。

原始受理记录保持不变。另存带版本的所有者授权修订，由运行时代码计算有效授权。路径相对于已受理的工作区进行规范化，展示精确的文件和命令变更，并依据宿主能力及强制排除规则校验。修订不能绕过沙箱限制，也不能授权宿主无法提供的命令。“go ahead”之类的普通文本不会扩大路径或命令 ID 范围。

有效的权限修订会使当前执行授权和受影响的基线失效。历史基线及批准仍可审计，但不能授权新工作。运行时必须根据有效授权生成基线，并在 Headsman、Ralph 或任何其他实施动作开始前，取得新的精确 Gate C 批准。所有者回答既不是 Gate C 批准，也不是 GO 或收尾授权。

分析仍然是分析：不能到达 Headsman、Ralph、Integrator、执行基线、Gate C 批准或收尾。最终结果仍为 reported。在分析中产生的实施请求，必须作为独立的实施运行重新受理。

### 返工计数

maxReworkPerGate 保持配置值，预设目前为 2，并按 GateRecord.gate 计数。所有者问题和回答保存在 gate 数组之外，不消耗自动返工额度。它们既不重置计数，也不产生无限重试循环；Ralph 的轮数上限不变。

在所有者提供实质性回答后，允许对受影响的 gate 进行一次明确关联的重新评估，即使其自动返工额度已用完。这是所有者新指示下的评估，而不是补充预算：后续 rework 结果仍沿用累计计数，超限时立即再次升级。已经消耗的相同回答不能授权再次评估。如果仍需新的所有者输入，且独立的重新评估额度尚未耗尽，应保存一个说明剩余障碍的新问题；没有这一新障碍，不得自动再次提问或重试。

通过经校验的 Config 字段 maxOwnerReassessmentsPerGate，单独限制所有者指示下的重新评估：它必须为正安全整数，默认值和预设值均为 2，并由 Loader schema 及直接配置解析共同检查。将上限保存在运行的持久化预算中，加载时校验。所有者台账按原 GateRecord.gate 独立计数；在宿主回合的步骤 3 中，将一次额度消耗、已接纳的回答及其恢复计划共同保存到同一个权威持久化检查点或台账修订中；步骤 2 的临时 RPC 保留和打开对话框都不算持久化消耗。重复回答、取消恢复、重启及进程配置变化都不能重置或重复扣除此计数。

使用预设时，每个 gate 最多允许两次所有者指示下的重新评估。两次额度用完后，再次需要重新评估必须终止于 escalated，并说明运行 ID、gate、已用次数、上限及未解决原因。已经保留的第二次评估仍可消费一次；上限拒绝的是第三次评估。不得为该 gate 创建新的所有者问题或恢复计划，也不得让 approve 或 answer_continue 重新开启它。已有待答问题仍可被拒绝，但拒绝绝不授予再次评估。此上限独立于 maxReworkPerGate 和 Ralph 轮数。

### 持久化与恢复

[记录格式](../../../../packages/conductor/conductor/src/state.ts) 在 P1 中采用 CONDUCTOR_RECORD_FORMAT_VERSION = 4，并以清晰的版本错误拒绝版本 3 和其他不支持的记录，不提供兼容层。#47 和 #30 第二阶段在该版本 4 基础上继续构建，不得各自重复占用版本 4。后续格式变更必须从届时的当前基线分配下一版本。

GateRecord[] 仅用于 gate 决定。新增只能追加的所有者交互台账，以及经单调性校验的记录修订号。每个问题将稳定 ID 绑定到根会话、运行 ID、原 gate 索引、阶段、精确子代理尝试、候选或报告哈希、授权修订号、必答条目 ID、原因以及具体提案。每次接纳的回答记录操作、答案、修订、先前修订号和单次使用的恢复计划。加载时校验台账与 gate 历史的因果顺序。绝不信任客户端提供的阶段、路径、角色或恢复参数。

这样可保留精确子代理的 [historyOffset 契约](../../../../packages/conductor/tool-conductor/src/children.ts)。不得将问题插入 run.history，也不得将后续 gate 结果悄悄归给先前的子代理。分析和实施两类记录校验器都必须理解待答与已答交互，而不能仅放宽 validateResumable。

问题不会自动到期：没有 TTL、空闲期限或因重启而失效的规则。关闭对话框、传输超时、客户端断开或宿主重启，都会让持久化问题继续待答，直到所有者明确回答，或运行的取消、替代已被记录。传输请求结束不等于问题结束。

浏览器重连会重新投影同一个待答问题。宿主重启后，从持久化台账重建问题，保留问题 ID，但生成新的传输请求 ID；旧传输回答会被拒绝。只有所属根会话中当前的运行、问题和修订号组合才能接收回答。完全相同的重复回答返回已有回执，不再次派发；冲突、跨会话或已被替代的回答必须明确失败。失效指传输请求、问题 ID 或记录修订号已非当前值，而不是经过了某段时间。

使用一个已完成的纯宿主交互回合，在安排继续执行之前记录回答：

1. 将待答问题持久化到 Conductor 检查点，并让原工具回合结束。仅在会话刷盘成功后，发布可回答的卡片。
2. 校验回答，并由宿主控制器保留精确的待答问题。RPC 处理器仅排入不透明的宿主保留凭据，不在回合之间追加会话事件，也不把回答文本变为工具参数。
3. 开启正常的宿主所有的后续回合。Conductor 专属的 agent/pre-step hook 校验存活的根代理和保留凭据，追加回答、授权修订和检查点，然后返回空的 enter 结果。[现有代理循环](../../../../packages/core/agent-loop/src/agent.ts) 可在不执行模型或工具的情况下完成这个回合。
4. 等待代理空闲和 sessions.flush() 成功，并在每次 await 后重新检查保留凭据及生命周期。之后才确认回答已持久化，并安排受限制的同一运行继续执行。
5. 恢复计划只消费一次。如需模型回合，第一个模型工具调用必须是该运行的 conductor，使用宿主持有的回答和已保存的受理信息。不得开放普通读写工具或新受理的运行。

[目标轮次驱动器](../../../../packages/goal/goal-round-driver/src/index.ts) 提供生命周期与刷盘屏障模式，但并不是已有的所有者恢复实现。新控制器和路由 hook 必须限定于 Conductor；不要修改指令优先级或通用代理循环。

[会话修复](../../../../packages/core/session/src/repair.ts) 会保留中断回合中已经完整写入的事件，并关闭中断活动。即使回合在回执之前中断，恢复过程也必须核对已写入的回答和检查点，避免重复应用。释放或取消绝不自动触发继续执行。已接纳的回答保留为等待继续执行，直到所属会话被明确恢复。

不要承诺崩溃情况下外部副作用恰好执行一次。如果已经派发，但其持久化子代理身份或结算状态不明确，应暂停并报告歧义，而不是再次派发。本设计假定每个会话存储只有一个写入方：当前进程内的保留机制不是跨进程 DSH_HOME 锁。[Session persistence: lock pr. DSH_HOME (#51)](https://github.com/Biyocon/biyocon-harness/issues/51) 是多进程运行的前提。在该 issue 实现并验证之前，应从操作层面排除第二个写入方；#37 不实现这把锁。

### 主代理路由、界面与来源

扩展 [Conductor 路由守卫](../../../../packages/conductor/tool-conductor/src/mode-routing.ts)，增加等待所有者和已保留继续执行的阶段。等待、完成、拒绝和停止的运行均不暴露普通主代理工具。问题待答期间到达的新用户消息，不得将守卫重置为新任务；应清楚地排队并保留其内容。只有宿主保留凭据才能恢复已保存的运行。工作区指令、专家文本、模型生成的操作 ID 或伪造的收件来源字符串都不能产生保留凭据。

增加 Conductor 专属的类型化交互意图，因为[当前计划评审视图](../../../../packages/client/ui-user-questions/src/client/contract/slots.ts) 不满足所需的三操作流程。卡片显示运行 ID、gate、角色和尝试次数、原因、所有必答问题，以及精确的拟议权限变更，并提供文本形式的等待、已接纳和已拒绝状态及无障碍控件。支持 EN/DA 和键盘操作。浏览器刷新后仍应显示相同问题及已接纳回执。

持久化问题创建、回答记录、继续执行消费和终止性拒绝的类型化会话事件，以及完整的 Conductor 检查点。所有新的所有者交互事件均为 required-on-read：省略信封中的 ignorable 字段，绝不设置 ignorable: true；ignorable: false 也不是有效信封。不认识这些事件的读取器必须拒绝重建会话。实施时定义其解码器及传输和 SDK 覆盖；仅增加事件类型不必修改通用会话格式版本。

使用 pnpm run gen-persistence-catalog 重新生成 [KNOWN_SESSION_EVENT_TYPES](../../../../packages/core/session/src/known-event-types.ts) 和持久化目录，所用的是[生成器](../../../../scripts/gen-persistence-catalog.ts)。用 pnpm run verify-persistence-catalog 检查这两个生成产物，该命令也由 doc-sync 运行；不得手工修改已知事件集合。模型可见的继续执行上下文必须由同一组规范事件投影：所有者的原文回答、有效授权修订号、证据引用，以及仍然需要的 Gate C 批准。不得声称未回答的问题已获批准，也不得声称实际未执行的专家已经运行。

现有角色、尝试和 gate 显示仍关联到精确子代理。所有者问题单独显示；如需重新评估，恢复时创建新的专家尝试。日志包含交互 ID 和 gate 决定，但不得复制凭据或无关的私有文件内容。

### 验证计划与文档归属

扩展 [conductor-installed.snapshot.ts](../../../../examples/headless-agent/tests/conductor-installed.snapshot.ts) 中真实的安装预设示例，通过实际交互接缝提供脚本化宿主回答。测试保持无密钥，并使用仓库外的临时工作区。[安装驱动器](../../../../examples/headless-agent/tests/fixtures/conductor-installed-driver.ts) 和[批准 fixture](../../../../examples/headless-agent/tests/fixtures/conductor-snapshot-approval.ts) 可作为起点；直接 mock Conductor 引擎并不足够。

- 覆盖 Strategist 提出两个计划问题和一个权限提案：回答一次，保留运行 ID，显示原升级，并重新评估受影响的 gate。
- 覆盖无需新权限的澄清、明确拒绝、交互提供方不可用、关闭对话框、浏览器重连，以及回答持久化前后和继续执行消费前的宿主重启。
- 验证传输请求或修订号失效、重复、冲突、会话错误、运行错误、修订号错误及伪造保留凭据的回答；保留排队中的无关用户消息，并拒绝主代理自行读写兜底。
- 验证累计返工计数及各 gate 独立的 maxOwnerReassessmentsPerGate 上限：允许两次所有者评估，第三次终止升级，重启不重置计数，不重复扣除额度。同时验证每个已接纳回答仅一次评估、授权改变后重新通过 Gate C、批准前不得写入，以及分析禁令保持不变。
- 在每个持久化边界和子代理派发歧义处测试取消；断言没有隐含授予、已接纳回答丢失或自动重复派发。
- 比对模型可见回答与 required-on-read 会话事件，并验证两类记录、版本 3 拒绝、精确子代理尝试及历史基线关联。未知的必需事件必须导致会话重建失败；生成与 verify-persistence-catalog 必须覆盖已知事件集合。待答问题必须在时间流逝后继续保留，不自动到期。
- 增加真实浏览器覆盖，验证 EN/DA 控件、多项必答、刷新、等待和拒绝。未来 GUI PR 的 GIF 从 3090 上的专用服务器录制，并发布到单独的 assets 分支；不得使用所有者在 10822 上的应用。
- 仅在新事件或 schema 产生影响时，更新现有模型可见 Conductor snapshots 及 TS/Python SDK 预期输出；实施时运行聚焦测试、类型检查、lint、doc-sync 和仓库推送前检查。

## 已考虑的替代方案

**A：使用 Conductor 专属控制器持久化暂停运行——推荐。** 支持多个问题、自由文本、重启恢复、精确权限绑定，并在所有者离线时不消耗模型活动。代价是增加交互意图、台账和生命周期集成，需要明确的竞态及恢复测试。

**B：保持 conductor 调用开启，等待现有问题或批准服务。** 生命周期改动较少，并可在同一宿主进程持续存活时工作。但待处理映射和存活的 promise 不提供持久化重启恢复；布尔式批准也无法表达所需答案。再增加持久化和恢复，最终会接近 A，却仍保留长时间运行的工具执行。

**C：将问题作为普通文本返回，让主代理发起新运行。** 不需要新界面交互，也能用于普通聊天。但会丢失同一运行身份，使来源和授权不明确，并重新开放模型主导的路由。不满足 #37。

## 验收标准

- 可恢复的 Gate B 升级，在持久化后成为可回答的宿主所有的问题；所有者回答恢复同一次运行，原 gate 及专家证据仍可见。
- 三种操作均有独立且经过校验的语义。必答项不可跳过；拒绝不派发任何专家，断线不授予任何权限。
- 只有经过校验的明确授权修订才能改变有效权限。每个受影响的执行基线都需要新的精确 Gate C 批准；分析保持只读，不能到达实施或收尾。
- Gate 记录、所有者交互、授权修订号和子代理尝试在重启后仍保持一致。返工与所有者重新评估上限各自累计、相互独立；所有者额度耗尽后必须终止升级并说明原因。问题不自动到期，失效或重复回答不能再次触发继续执行。
- 完整性故障和被拒绝的 Gate C 授权仍为终止状态。等待或处理所有者回答时，主代理不能自行调查、写入或另起替代运行。
- 无密钥的安装预设 snapshots、恢复测试、EN/DA 浏览器检查及受影响的 SDK fixtures 覆盖拟议契约；宿主脚本化场景不需要真实 API 录制。

## 风险

主要实施风险是持久化控制器的边界、在不重置返工预算的前提下执行独立的所有者重新评估上限，以及版本 4 记录变化。三个实施 PR 均须停止等待所有者和 Claude 评审；仅批准设计不代表授权实施或合并。

类型化修订预览不可缺少：如果自由文本能暗中扩张权限，就会重现原有安全问题。恢复过程不得声称具备当前宿主无法保证的跨进程锁或恰好一次派发。安全的多进程操作依赖上文链接的 DSH_HOME 锁 issue；设计假设不等于已经执行锁定。

暂停的交互需要明确的等待与取消状态，避免看起来像已完成。问题及回执可能包含敏感项目信息；应保存在现有会话存储中，并避免在事件、示例、GIF 或日志中包含无关内容。本设计不增加提供商、秘密存储或保留策略。
