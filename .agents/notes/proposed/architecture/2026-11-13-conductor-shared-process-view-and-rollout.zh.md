# Agent Note: 共享 Conductor 流程视图与经验证的更新

Status: proposed

[English](2026-11-13-conductor-shared-process-view-and-rollout.md) | 中文

## 问题

Harness 与 Super-Desktop 提供不同的流程界面，并嵌入不同修订版的引擎。相同头像、版本字符串或已完成的工作者不能证明 gate、所有者权限或运行中应用的更新一致。即使打包成功，两套独立的记录解释逻辑也会逐渐偏离。

## 提案

在[可移植组合包交付计划](2026-11-11-portable-conductor-bundle.md)基础上增加一个规范、带版本的展示模型，以及两个应用的联合验证。本提案是仓库内的评审依据；外部协调文件仅提供信息。只有所有者能授予决策、合并及 Gate C 授权；计划确认不授予任何此类权限。Conductor 代码保留在自己的包和独立 UI 插件中；任何必要的通用核心修改都必须在[依赖清单](2026-11-05-conductor-core-dependencies.md)记录文件、用途和 PR（Pull Request）编号。核心不得导入 Conductor。

### 交付顺序与归属

Harness-Codex 负责引擎、宿主组合包及 Harness 绘制层；PI 侧负责人负责单独授权的 Super-Desktop 集成。双方分别使用自己的 worktree 和可变输出。建议每个仓库同时只有一个实现 PR，且不建立推测性的依赖堆栈。每项前置交付均须通过正常检查、评审及所有者控制的合并后，才能被下游使用。

| 里程碑 | 必需交付及依赖 |
| --- | --- |
| R0 | 分别记录源码及基线、宿主、引擎和资源哈希、构建产物与实际运行身份。明确范围和归属；源码合并不等于应用已更新。 |
| R1 | [#113](https://github.com/Biyocon/biyocon-harness/pull/113) 合并后，向 master 提交一个草稿实现 PR，包含 `## Resumé (dansk)`。在持久化读取或重放前，注册来自已组合配置的必需事件声明，并保留下述四项证明。 |
| R2 / 4a | R1 交付后，仅使用打包产物验证干净的 rc.7 安装，不使用 workspace 链接、源码副本或手动 preset 转移。 |
| R3 / 4b | 4a 通过后，使用相同规范引擎产物及对应的薄宿主组合包，对一个固定修订版的新宿主重复兼容性验证。Biyocon 继续使用 rc.7。 |

| R4 | 向 PI 交付已验证的引擎／宿主／UI 导出、模型版本、产物哈希、支持的记录、宿主矩阵和拒绝规则；不依赖草稿或隐式更换固定版本。 |
| R5 | 在改变所有者操作访问方式前，完成独立的适配器／共享聊天设计、所有者明确决策，以及会话和传输绑定的安全评审。 |
| R6H / R6S | R5 获批后，各负责人仅实现必要的宿主／后端集成，并证明从生产方到投影的来源链。PI 只能通过明确、经验证的交付更换引擎固定版本。 |
| R7H / R7S | 两个应用绘制相同投影及已评审的聊天布局。它们是两个绘制层，不是两套后端解释逻辑。 |
| R8–R11 | 完成联合验收、最终源码集成验证、单独授权的数据安全更新，再验证两个实际运行产物并由所有者验收。候选变化后重新验证受影响的证据。 |

R1 必须证明：合成 Conductor 历史在启用组合包时可打开；缺少组合包时在重放前明确拒绝；普通聊天无需组合包仍可使用；冷启动既不重写历史，也不重复模型或工具工作。启用组合包时，不受支持的运行记录仍保留聊天及不可用状态，但实际运行操作继续拒绝。这些证明是打包安装门禁的补充，不能替代后者。[隔离质量演练](../testing/2026-11-13-conductor-isolated-quality-rehearsal.md)是独立工作，不阻塞 R1。

### 单一版本化展示模型

R4U 在 `packages/conductor/*` 中维护一个纯事件／运行记录投影，由两个应用共同使用。输出版本独立于 Conductor 记录格式 5；未知模型版本必须明确失败，不能退回各应用自己的解释逻辑。输出包含运行／角色／dispatch 身份、尝试、gate、证据、返工及失效、明确跳过的步骤，以及能追溯来源位置和哈希的所有者交互状态。宿主、引擎和交互生命周期分别保留。

输入必须指定一致的运行记录／事件前缀，以及经宿主确认的持久化确认位置。R4U 必须定义并测试如何确定该位置；流式检查点、已完成工作者、绘制层状态或模型文本都不能伪造确认。只有经过验证的记录及必需证据处于已确认前缀内，gate 才能显示为通过。矛盾、无效或不受支持的输入只产生明确诊断／不可用状态，不能产生看似成功的状态或迁移。测试同时覆盖不完整前缀、延迟确认和完整重放。

按精确的根会话、运行、问题及修订号折叠所有者问题和已确认回答；每个问题／修订最多呈现一个活动表单。历史回执只读。描述表单的元数据不授予提交权限。宿主传输预留、单次消费、拒绝及持久化确认仍是权限依据。两个绘制层只消费投影状态，不重新计算 gate、不自行选择另一个最新记录，也不从文字中解析裁决。

无密钥测试使用合成的有效、无效和不受支持记录，以及过期／错误运行／重复问题、多次尝试、返工、缺失证据和重新加载场景。两个应用消费相同版本的投影 fixture（测试前置数据），证明语义等价；原生视觉测试验证实际呈现。fixture 或日志不包含私有会话内容。

### R5 所有者决策与共同聊天目标

在两个应用中提供相同的所有者表单，会改变 [#111](https://github.com/Biyocon/biyocon-harness/pull/111) 的决策：适配器 v1 仅允许 start/status/result/resume，拒绝在等待所有者时 resume，并将所有者回答和批准留在宿主 UI。本路线图或投影导出均不批准此变更。实现前，R5 必须取得所有者明确的新决策，并评审会话／传输绑定、可信宿主归属、过期／重复回答、持久化和重放的安全性。内部类型是设计参考，不是已批准的外部所有者 API。

评审一套聊天内流程卡片／时间线，统一角色／尝试／gate 顺序、报告／证据、返工、错误，以及带历史回执的单一活动所有者区域。单独仪表盘或指向其他宿主表单的链接，本身不算完整的聊天内一致性。固定 EN/DA 参考视图、键盘／焦点行为和明确列出的平台例外。Super-Desktop 的丹麦语支持是计划工作，不能从现有语言数量推断。

各宿主使用隔离数据，每个运行由一个宿主拥有。共享主目录的写入者或同一运行的并发客户端，要求单独批准并实现 [#87](https://github.com/Biyocon/biyocon-harness/pull/87)，并验证宿主访问。保护所有者的活动应用／数据；验证期间不迁移或恢复私有运行。#75/#30/#58 的共享 v6 设计仍独立处理；当前格式的 UI 验证不需要记录升级或虚构 `incomplete` 状态。

## 考虑过的替代方案

**两套记录解释逻辑。** 最初使用相同 fixture，也无法避免 gate、证据或所有者语义日后偏离；应共享纯投影及版本协商。

**通过路线图批准表单。** 这会隐式扩大适配器 v1 权限；R5 必须保留为新的所有者／安全决策点。

**将 checkout 测试当作安装或更新证明。** 它们不能证明打包依赖闭包、另一宿主的行为或运行中应用身份；4a/4b 和切换验证必须独立保留。

## 验收标准

每行均针对两个精确候选运行，使用合成输入、已确认的后端回执、投影版本／哈希、原生证据及明确的通过／失败／未运行状态。底层测试不等于整应用验收；无密钥 fixture 不证明真实模型质量。

| ID | 必需场景与可观察结果 |
| --- | --- |
| P01 | 打开历史不触发 dispatch、提供方调用或写入。 |
| P02 | 只读分析显示实际角色、明确跳过的步骤及真实结果；没有写入。 |
| P03 | 实现流程证明 Conductor 加上七个专家的实际 dispatch、真实且无害的范围内修改、精确 C 批准／适用工具许可，以及新鲜独立的 D/E 执行。打印角色名不算证明；Ralph 必须有真实 dispatch。 |
| P04 | 澄清和授权范围修改绑定精确问题／修订／条目及提案哈希；不隐式批准执行。 |
| P05 | Gate C 与工具许可相互独立；基线变化使同意失效。 |
| P06 | 错误运行、过期、重复及并发回答失败，不重复继续执行，也不提前显示成功。 |
| P07 | 计划／设计及实现返工保留尝试、目标和下游失效记录。 |
| P08 | GO/NO-GO 和分析结果来自已验证引擎记录；不授予外部交付权限。 |
| P09 | 缺少必需目录属于设置问题；初始执行证据为空正常；准入配置变化要求新运行。 |
| P10 | 缺少／篡改引擎或组合包，以及无效／不受支持记录，遵循拒绝／不可用规则，不产生虚假成功。 |
| P11 | 重新打开、重新加载和冷启动保留历史，不重复工作或重写记录。 |
| P12 | 取消／中断／清理失败阻止迟到回调，并显式显示不确定效果。 |
| P13 | 聊天切换、延迟读取及重连不能更新另一个运行／会话。 |
| P14 | 比较共同 EN/DA 视图、实际截图／交互录像、鼠标／Enter／Space、焦点和窄布局；保留其他语言。 |
| P15 | 新安装、支持的历史和不兼容降级均有明确且保护数据的接受／拒绝规则。 |
| P16 | 所有者授权更新后，两个正常应用入口报告所交付的引擎／组合包／UI 身份，并通过约定冒烟测试。 |

## 风险

持久化位置可能需要小型通用宿主扩展；不得推断确认或放宽安全要求来回避它。部分 UI 重构可能破坏现有卡片，须保留对应证据和可运行 snapshot。范围相关的输入、哈希和错误不得泄漏秘密。所有者可以拒绝 R5；先前的 v1 安装／视图工作仍有价值，但不能声称已实现完整表单一致性。

替代审计：可移植组合包提案继续负责打包、重放及 v1 权限；本注记补充交付／投影细节和明确的后续决策点。[rc.7 交付片段](../../implemented/architecture/2026-11-12-conductor-rc7-host-bundle.md)、[所有者恢复](../../implemented/feature/2026-10-30-conductor-owner-escalation-resumption.md)、[子会话状态](../../implemented/bug-fix/2026-10-28-conductor-child-role-status.md)、[不可用历史](../../implemented/bug-fix/2026-11-06-conductor-unsupported-record-history.md)及[会话格式规则](../../implemented/architecture/2026-08-10-session-log-version-mechanism.md)继续保有独立、有效的保证。没有已实现的完整三文件组被完全替代或归档。
