# Agent Note: 分析质疑结果的隔离验证基础函数

Status: implemented

[English](2026-11-02-conductor-analysis-critic-primitives.md) | 中文

## 问题

[英文分析批评者设计](../../proposed/feature/2026-10-28-conductor-analysis-critic.md)和[中文设计](../../proposed/feature/2026-10-28-conductor-analysis-critic.zh.md)要求把批评结果绑定到精确候选报告及已准入证据。如果在现有分析驱动器中解析批评结果或选择证据，就会在完整的记录和派发语义就绪前改变运行中的路线。当前 v4 分析运行必须保持原有行为和字节一致的快照。

## 决策

[质疑结果验证](../../../../packages/conductor/conductor/src/analysis-challenge.ts)和[已捕获材料选择](../../../../packages/conductor/conductor/src/analysis-materials.ts)是内部纯函数模块。已准备的批评分派通过源码子路径导入它们；当前分析驱动器和包入口不导入。函数本身不会产生检查点、事件、配置值或公开包导出。

质疑结果验证器将模型结果视为不可信输入。它检查运行、候选版本和哈希、有序材料 ID、批评者身份与尝试次数、发现、结论及条件性 `defect` 字段。同一个语义检查会拒绝重复的材料或发现 ID、引用质疑结果自身材料之外的发现，以及与发现严重程度不符的结论。验证、质疑结果哈希计算以及对每个 `previous` 质疑结果的验证都使用该检查，因此语义无效的结果不能获得哈希。`does_not_hold` 必须带有 `scope | plan | report`；`holds` 禁止 `defect` 及未解决的 major 或 critical 发现。来自其他运行、已经过时、互相矛盾或与路线冲突的结果会验证失败。类型化缺陷是后续返工路由的唯一依据；自由文本发现不能选定角色。

材料行区间标识已准入的捕获材料及首尾均包含的行号。验证会核对捕获内容与所记录哈希，拒绝缺失、变化或越界的材料。独立于运行时的选择器按稳定的材料及区间顺序排列，将引用行以 LF 连接。它按传入的 token 上限计量所构造的完整批评者提示，包括指令、候选报告、验收标准、材料索引及摘录；超限时失败，绝不截断。提示在专用的结构化 `identity` 字段中包含由运行时提供的运行、候选报告及批评者身份，还有预期材料顺序。函数重新计算候选报告哈希后才接受该身份；区间、摘录及解析后的质疑结果材料 ID 均使用 `ConductorMaterialId`。上下文将 `criticAttempt` 定义为整个运行期间递增的编号，包括新候选版本；P2 在派发时分配该编号。这为可记录、可重建的输入做准备，同时不允许批评者探索仓库或自行挑选摘录。

## 考虑过的替代方案

**立即将函数接入 v4 驱动器。** 这样会在生产者/批评者 Gate C 模式、质疑结果持久化及 Arbiter 绑定形成最终 v5 含义之前，提前暴露不完整的批评路线。保持函数为内部实现，使现有运行约定不变，同时可独立测试验证逻辑。

**让模型从自由文本选择证据或返工目标。** 未记录的文件探索与根据文本推断的路由无法可靠重放。捕获哈希、类型化区间及类型化缺陷类别使两个决定均可检查。

## 后果

Conductor 仍运行现有分析路线，持久化格式 4，并产生相同快照。已准备的批评分派仅在被明确选择时使用隔离模块；当前路线不会增加批评者 token 或模型可见输入。单元及属性测试以 100% 源码覆盖率固定模式校验、过时和矛盾结果的拒绝、区间/哈希验证、确定性有界摘录及稳定的质疑结果哈希。链接的提案负责后续路线、持久化及所有者升级的变更。
