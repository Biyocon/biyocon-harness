# Agent Note: 通过持久化所有者问题恢复 Conductor 升级

Status: implemented

[English](2026-10-30-conductor-owner-escalation-resumption.md) | 中文

## 问题

[Issue #37](https://github.com/Biyocon/biyocon-harness/issues/37)描述运行 CON-2026-4272：Strategist 请求六个文件的权限及两个计划选择的澄清，但 Gate B 升级后没有询问所有者。另开运行会丢失问题、专家证据和回答之间的关联。反过来，若任何升级都能恢复，回答就可能绕过必需的完整性或授权检查。

[Gate C](../../../../packages/conductor/tool-conductor/src/index.ts)已获取绑定精确执行基线的宿主批准。一次性权限决定不能收集必需的自由文本澄清，也不能建立持久化的同运行恢复。仅有活动 RPC Promise 无法在宿主重启后重建问题。

## 决策

可恢复升级转为持久化所有者问题。Conductor 自有控制器通过类型化交互收集所有者的完整回答，在无模型宿主回合中记录，并为同一运行保留一次受限继续执行。随附预设启用该生产路径；[问题 UI](../../../../packages/client/ui-user-questions/README.md)渲染专属 Conductor 卡片，不复用计划审阅。七个专家角色、按目的区分的路线和门禁职责保持不变。

### 分类与阶段转换

只有明确澄清、宿主可验证的具体授权提案和耗尽的可恢复报告返工能请求所有者输入。身份、路由、未授权执行、基线篡改、沙箱违规、Gate C 批准被拒和通用故障仍为终止。异常措辞绝不使其变成可批准问题。分析只接受专用只读澄清，不能获取实现权限。

| 条件 | 持久化结果 | 允许的后续操作 |
|---|---|---|
| 门禁 X 的可恢复升级 | `awaiting_owner` | 成功 flush 后显示已持久化问题。 |
| 完整有效回答或批准具体提案 | `continuation_pending` | 记录一次所有者指示的重新评估计划。 |
| 所有者拒绝 | `aborted` | 保留拒绝，不再派发专家。 |
| 关闭、断开连接或应答者不可用 | 问题保持待答 | 不授予权限，保留同一持久化问题。 |
| 完整性/安全故障或所有者预算耗尽 | 终止升级 | 说明未解决原因，不提供新的继续操作。 |

门禁历史仅追加。重新评估添加新的子会话尝试和门禁结果，绝不把旧升级改成通过。普通澄清返回原角色。使计划失效的授权变更在进一步实现前返回 Strategist 和 Devil's Advocate。问题不进入 `GateRecord[]`，保留精确子会话的[历史偏移归属](../../../../packages/conductor/tool-conductor/src/children.ts)。

### 操作与权限

UI 将英/丹标签映射至机器操作 `approve`、`reject` 和 `answer_continue`。标签和回答文本绝不授予权限。回答原子地覆盖所有必答条目 ID，要求有界非空文本及有效机器选项 ID。没有默认选择。关闭面板、跳过必答项或断开连接都不构成同意。

只有宿主验证的具体提案才显示批准。卡片展示允许路径、排除路径和质量命令 ID 的精确变更前/后值。批准授权变更的回答明确确认该展示提案，并提供必需澄清。普通回答不能悄然接纳额外路径或命令。

原始准入保持不可变。运行时从独立版本化授权台账派生有效权限，针对准入工作区和强制排除规则验证规范路径，并通过宿主能力解析命令 ID。变更不能放宽沙箱约束或授权不可用命令。它使当前授权及受影响基线失效；历史批准仍是证据，不是新工作的权限。Headsman、Ralph 和实现效果仍须获得全新精确 Gate C 批准。所有者回答绝不是 Gate C 批准、GO 或 closeout。

分析保持空执行授权，不能到达 Headsman、Ralph、Integrator、Gate C 批准或 closeout。接受结果仍为 `reported`。实现建议需要独立实现运行。

### 独立重新评估预算

`maxReworkPerGate` 保留独立门禁计数和预设值 2；所有者回答既不消耗也不重置自动额度。Ralph Round 限制不变。即使自动返工耗尽，有效回答也允许一次关联重新评估，但后续返工仍看到累计门禁计数。

`maxOwnerReassessmentsPerGate` 是经 Loader 及直接配置解析验证的正安全整数，默认/预设均为 2，并随运行持久化。接受回答并预留恢复计划时，在原门禁的所有者台账中原子消耗一次额度；打开卡片或预留 RPC 不消耗额度。第三次请求转为终止升级，注明门禁、计数、上限及未解决原因。已经预留的第二个计划仍能消费一次。重启、重复回答和配置变更不会重置或重复扣减任何预算。

### 持久化与恢复

`CONDUCTOR_RECORD_FORMAT_VERSION = 4` 在普通门禁之外存储仅追加所有者台账及单调验证的修订号。版本 3 和其他不支持的记录明确失败，不做迁移。[#47](https://github.com/Biyocon/biyocon-harness/issues/47)和 [#30 第二阶段](https://github.com/Biyocon/biyocon-harness/issues/30)在此基础上构建，任何后续版本必须依据当时基线分配。

每个问题将稳定 ID 绑定至根会话、运行、门禁索引、阶段、精确子会话尝试、报告/哈希、授权修订号及必答条目 ID。接受的回答绑定操作、完整答案、可选变更、前一修订号和一次性计划。分析及实现验证器都重建该因果历史。客户端提供的阶段、角色、路径或恢复参数不能替换宿主数据。

问题没有 TTL，也不自动过期。浏览器刷新从持久事件重建同一问题及接受/拒绝回执。宿主重新连接为同一待答问题绑定新的传输 ID。回答必须匹配当前运行、问题、修订号、传输和精确活动根。相同的已记录回答返回保存回执，不再次派发；失效、冲突、外来及伪造回答明确失败。

宿主控制器保持以下顺序：

1. 保存待答问题并 flush Session，再展示可回答交互。
2. 验证回答并预留精确问题。现有 `agent/inbox/spliced` 事件可以先于宿主回合，但只含不透明预留及中性插件文本。答案、选项、授权变更和检查点绝不进入该队列。控制器状态验证归属和一次性消费，不信任消息文本或来源字符串。
3. Conductor 专属 `agent/pre-step` 钩子在正常宿主回合记录回答、授权变更和检查点。只有检查点 flush 成功后，才追加必读 `conductor/owner-response-acknowledged` 标记，证明此前回答已持久化，随后返回空输入，不运行模型或工具步骤。该标记始终位于同一宿主回合，本身不授予继续执行权限。
4. agent 空闲且 `sessions.flush()` 成功后，确认持久回答，只安排其受限继续执行。跨异步边界重新检查活动状态和取消。
5. 在专家派发前仅消费一次保存计划。如果需要模型步骤，其首次工具必须是预留运行的 `conductor`。明确记录的插件上下文投影持久回答、有效授权及仍需获得的 Gate C 批准。

不改变通用 agent loop 或工作区指令优先级。用户/模型复制预留文本不能创建继续权限。等待期间的新用户消息保留在可见队列；等待、继续执行预留及完成/停止结果期间拒绝普通父级工具。

恢复将完整写入的必读所有者事件与中断检查点协调，不重复应用答案。没有持久回答的队列标记会安全失效，问题保持待答。有持久回答但计划未消费时保留显式恢复能力。取消和释放绝不自动继续。若可能已派发，但持久化子会话身份/结算不明确，运行保持停放而不再次派发。

持久接受但计划尚未消费的回答在重启后继续停放；创建 agent 绝不自动派发。宿主先在无模型宿主回合协调并 flush 缺失确认，再提供 `mode: continuation` 的类型化 `conductor-owner` 卡片。它展示已保存接受及先前问题，不提供可编辑答案、权限或提案控件。唯一操作是显式 `answer_continue`，答案为空且无提案哈希。新的私有传输预留验证精确根、运行、问题、当前答案修订号及未消费计划，再调用现有 `resumePending` 路径。这不记录第二次回答，也不额外消耗所有者重新评估额度；重复消费及失效/外来传输均失败。

五种 required-on-read 会话事件记录问题创建、回答、回答确认、继续执行消费和终止拒绝。四种台账事实先于其完整检查点；确认在宿主回答回合内成功 flush 回答检查点之后记录。均不带 `ignorable`。解码器验证台账及传输身份；SDK 投影覆盖这些事件。`pnpm run gen-persistence-catalog` 拥有 `KNOWN_SESSION_EVENT_TYPES` 与持久化目录，由 `verify-persistence-catalog` 检查。模型可见继续上下文另行记录且可重建。

这是进程内预留，不保证外部效果恰好一次，也不是跨进程存储锁。[Session persistence: lock pr. DSH_HOME (#51)](https://github.com/Biyocon/biyocon-harness/issues/51)仍是多个进程共享同一 home 前的必要条件。锁交付前，每个应用/测试服务器使用隔离存储。

### 父级路由、UI 与来源

类型化 Conductor 卡片显示运行 ID、门禁、运行时角色及尝试、原因、所有必答问题和精确提案变更。它提供文本等待/接受/拒绝状态、英/丹外框文案和原生键盘无障碍控件。持久化会话渲染在刷新后保留问题及回执。单独的回答/拒绝事件不足以显示接受/拒绝回执，因为它们可能在 flush 前就被推送。UI 要求匹配的 flush 后确认标记；缺少该标记时，即使传输已取消，状态仍显示等待且不展示答案文本。未提交表单草稿是本地 UI 状态，不是持久化同意。

回答仅通过生产提供者和 P2 控制器。UI 文本不选择阶段、不授权工具，也不提供模型参数。原有角色/尝试/门禁行仍关联精确子会话，问题是独立交互。恢复可创建另一专家尝试，不覆盖先前结果。

[准入](2026-10-25-conductor-intake-and-report-completion.md)、[门禁稳健性](../bug-fix/2026-10-25-conductor-gate-robustness.md)、[路由](../bug-fix/2026-10-25-conductor-mode-routing.md)、[批准 seam](2026-07-06-approval-seam.md)及[子会话状态](../bug-fix/2026-10-28-conductor-child-role-status.md)决策保留其独立约定并互相链接；没有完全取代或归档任何说明。

## 验证

真实[已安装预设示例](../../../../examples/headless-agent/tests/conductor-installed.snapshot.ts)在外部工作区通过交互服务运行脚本化宿主回答，而非模拟 Conductor 引擎。它们固定同运行澄清/变更/拒绝、必答项、父工具拒绝、模型可见答案投影及待答/不可用状态。域/控制器测试覆盖独立计数、精确传输绑定、重复回执、伪造预留、持久化边界取消、中断写入、已确认但未消费时重启不自动派发、显式一次性继续且不重复扣减预算，以及已消费但派发不明的状态。必读事件解码器、目录时效和 TS/Python SDK fixture（测试前置数据）保持各自覆盖。

真实 web 测试通道以无密钥回放覆盖英/丹控件、多个必答项、拒绝、等待、回答前后刷新及键盘使用。Web golden 从可运行场景生成。GUI 演示使用端口 3090 的隔离分支服务器/home 和独立 assets 分支，不触碰所有者端口 10822 的应用，也不暴露私人任务数据。

## 考虑过的替代方案

**持久化停放运行与 Conductor 自有控制器。** 选用，因为自由文本、多问题、重启恢复和精确权限绑定需要持久状态及显式所有的继续能力。代价是类型化交互、台账和生命周期测试。

**在现有批准/问题 Promise 上保持原工具调用。** 拒绝，因为活动待处理映射不能重建宿主重启状态，布尔批准也不能表达完整澄清。添加持久恢复最终会收敛至所选控制器，同时仍保留长时间工具调用。

**返回普通问题文本并让父级另开运行。** 拒绝，因为它丢失同运行证据，使授权含糊，并重新打开模型主导路由。

## 后果

所有者可以在应用中回答可恢复升级，不丢弃运行或专家证据。生产回答完成 #37 的三阶段交付；它不授权合并、发布或批准基线以外的实现。等待不消耗模型工作，每次接受的重新评估增加有界专家工作。

问题/答案历史可能包含敏感项目信息，仍保存在现有 Session 存储；不引入新模型提供者、秘密存储或保留策略。明确状态和精确预览防止停放运行看似完成，也防止自由文本悄然扩大权限。不支持的旧运行需要重新准入，跨进程运行仍依赖 #51。
