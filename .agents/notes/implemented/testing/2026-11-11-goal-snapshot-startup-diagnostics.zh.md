# Agent Note: 目标快照的启动诊断

Status: implemented

[English](2026-11-11-goal-snapshot-startup-diagnostics.md) | 中文

## 问题

目标 Round 与收尾的 ACP 快照要求 stderr 为空，但交付的 ACP 组合会打开派生 SQLite 查询索引。该索引导入 `node:sqlite` 时，Node 24.13 会输出实验性功能提示，导致成功的目标生命周期在执行记录断言之前就失败。

## 决策

这两个目标快照接受无输出或恰好一条完整的 Node SQLite 启动提示。匹配器锚定原始字符串的两端，允许进程 ID 数字以及 LF/CRLF 行尾，并要求警告文本与 trace-warnings 提示精确一致。它不会删除、规范化或抑制诊断。未知警告、不完整或重复提示、额外换行、错误及堆栈均使测试失败。

选择构建模式时，现有启动解析器已经能从 `src/bin.ts` 推导出 `lib/bin.js`，因此无需显式覆盖构建入口或更改启动器。警告来自正常的查询引擎，而非回退到源码模式；生产组合与 SQLite 使用方式均不变。

[ACP 回放机制](2026-06-19-acp-snapshot-tests.md)和[目标 Round 生命周期](../feature/2026-07-19-same-session-goal-round-driver.md)保持不变。本决策仅负责两个目标场景的启动诊断断言。

## 验证

诊断的正反例固定精确允许的输出。两个真实 ACP 场景通过源码入口和构建入口回放现有 fixture，并保留目标 Round、取消、收尾以及协议／会话 golden 断言。不重写 fixture 或预期执行记录。

## 考虑过的替代方案

- **抑制所有 Node 警告或清洗 stderr**：会隐藏无关的启动失败，并削弱其他场景的诊断断言。
- **在目标 fixture 中禁用查询索引**：会改变生命周期证明需要覆盖的交付组合。
- **要求显式构建入口**：只会重复解析器现有的路径推导，无法解决警告。

## 后果

不输出提示的 Node 版本与输出精确已知提示的版本共享同一生命周期证明。诊断文本变化仍会触发需要审查的测试失败；其他快照套件与生产 stderr 不受影响。
