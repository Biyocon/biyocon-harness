# Agent Note: Subagent-control 测试 fixture 的所有权

Status: implemented

[English](2026-11-11-subagent-control-fixture-ownership.md) | 中文

## 问题

Subagent-control 套件在测试后删除 JSONL 暂存目录，却没有关闭大多数 Cordis 根上下文。对未修改套件的本地观察显示：十五项测试全部通过后，仍保留十三个上下文和十四个已注册 agent；十二个目录消失时，其注册表仍包含 agent。进程退出不等于 fixture 完全停稳后清理。测试失败还可能让脚本模型一直等待无法执行到释放代码的关卡。

## 决策

[套件](../../../../packages/subagent/tool-subagent-control/tests/tool-subagent-control.spec.ts)拥有每个创建的上下文、暂存根目录和模型关卡。清理先启动上下文释放，释放全部自有关卡，再等待所有释放完成，最后删除暂存数据。这包括部分构建的 fixture 和插件卸载场景。关卡释放是幂等的，既保留正常测试调度，也允许在断言提前失败后完成清理。

任何上下文关闭失败时，清理仍等待其他上下文，报告聚合错误，并保留失败的所有者和全部暂存目录，以供后续清理。关闭状态不确定时绝不删除文件。现有删除重试设置不变；不修改结算期限、轮询策略或产品生命周期。

[可检查的结算断言](2026-11-11-subagent-settlement-assertion.md)仍独立必要。关闭 fixture 所有者修复的是已验证的测试资源泄漏，而不是已经证明了 [#67](https://github.com/Biyocon/biyocon-harness/issues/67) 历史激活超时的原因。该 issue 仍保持开放。

## 验证

真实的被阻塞子 agent 必须排空并使 agent 注册表为空，删除回调才可删除仍存在的目录。释放器失败案例证明其他上下文仍关闭，同时保留全部目录。聚焦控制套件保留原有激活断言和覆盖率。观察器比较测试完成时的实际注册表条目，而不是作用域服务代理的对象身份。

## 考虑过的替代方案

- **依赖 worker 退出或垃圾回收**：两者都不能保证在下项测试开始或文件消失前关闭每个 fixture。
- **仅释放关卡而不等待上下文释放**：最终持久化和模型工作仍可能与删除竞争。
- **延长激活移除等待时间**：无法修复 fixture 所有权，还可能隐藏未解决的活性失败。

## 后果

清理拥有未完成的工作，并显式暴露释放失败，不改变运行时行为、模型输出、快照或持久格式。诊断观察器及其原始元数据保留在本地；提交的 fixture 仅包含合成测试数据。
