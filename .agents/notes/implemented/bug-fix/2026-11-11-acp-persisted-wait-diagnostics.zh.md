# Agent Note: 慢速读取期间保留持久状态等待的超时诊断

Status: implemented

[English](2026-11-11-acp-persisted-wait-diagnostics.md) | 中文

## Problem

[#101](https://github.com/Biyocon/biyocon-harness/issues/101) 暴露了 ACP 快照等待的问题：拒绝时返回 Vitest 的通用超时，而非正在等待的状态。`vi.waitFor` 只有在异步回调拒绝后才保存其错误。如果截止时间在首次日志读取期间到达，就尚无回调错误。即使日志正确地不满足指定条件，coverage 负载也可能暴露这个窗口。

## Decision

[ACP harness](../../../../packages/test-support/acp-snapshot/src/harness.ts) 的七个异步持久状态等待共享一个私有轮询器。初始错误在 I/O 开始前指明等待的状态。已完成但失败的检查替换该错误，保留现有解析和 I/O 诊断。截止时间保持不变，到期时以最近一次已完成的失败拒绝；随后到达的成功检查不能满足等待。检查仍按现有间隔串行执行。同步工作区标记等待继续使用 `vi.waitFor`。

一个控制器停止间隔等待，轮询器返回之前等待当前检查结束。此 harness 无法取消文件系统读取，因此等待读取结束可能使清理超过状态验收的截止时间。它既不在超时后启动新检查，也不接受迟到结果。场景清理在读取结束后仅移除自有临时路径。Agent 运行时、模型输入、会话格式、导出签名和可调参数均不改变。

## Alternatives considered

**延长超时或重试 CI。** 更慢的首次读取可能超过任何固定期限；两者都无法在读取之前建立诊断。现有限制保持有效且不变。

**匹配并替换 Vitest 的通用错误文本。** 这会使 harness 依赖库内部消息，而且不能保证临时目录清理之前待处理的 I/O 已停止。

**使用 `expect.poll`。** 当前安装的实现允许在期限到达后进行最后一次检查，并可能接受迟到的成功。持久状态就绪等待要求现有期限拒绝这种结果。

## Consequences

即使首次检查尚未完成，超时也会指明请求的持久状态。更早的已关闭轮次、开放轮次、不完整 JSONL 记录和格式错误的开始记录仍被拒绝。已完成检查的错误保留原有身份；未完成的检查不能提供尚未观察到的错误。

回归用例通过真实的 `runScenario` 子进程执行，并将真实合成日志的读取延迟到原有 20 ms 期限之后。较早的已关闭轮次和迟到才读出的目标轮次都以明确诊断被拒绝。读取与清理观测验证临时目录移除不与待处理读取竞态。所属测试覆盖七个消费者；构建后的无密钥 ACP 回放检查取消与后台完成，不修改 fixture 或 normalizer。证据仅使用合成会话。
