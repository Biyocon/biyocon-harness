# Agent Note: Conductor 所有者路径、报告修复及真实结果

Status: implemented

[English](2026-10-25-conductor-gate-robustness.md) | 中文

## 问题

[Issue #27](https://github.com/Biyocon/biyocon-harness/issues/27)记录了一次已分派 Detective、Strategist 和 Devil's Advocate，却只返回 Gate C 路径验证阻塞的运行。父级无法区分这些进度和分派前失败。模型编写 baseline 路径还会让结构错误报告停止运行，而共享返工计数使一个门禁消耗另一个的修复预算。

## 决策

运行时拥有完整执行 baseline。Gate C 专家只提议范围、计划及验收版本、rollback reference 和质量命令 id。Schema 省略所有者路径。解析器拒绝专家编写路径，只复制运行获授权的 `allowedPaths` 和 `excludedPaths`；命令绑定仍由宿主解析。报告不能扩大范围。在 Headsman、Ralph、质量执行或 Integrator 获得其现有能力之前，完整 baseline 仍须获得精确宿主批准。

### 报告缺陷和权限故障

格式错误 envelope、已完成 child 缺失结构化输出、无效 baseline 提案和格式错误 Arbiter 决策使用 `report` 返工，返回同一报告角色。驱动器先记录拒绝及检查点，再启动全新 child。无效报告不进入已验证专家报告列表；原始模型输出仍保留在 child 日志。结构验证在下游使用之前检查嵌套证据、发现、变更请求及交接元数据。

身份、被评估来源、路由、质量证据或权限违规立即升级，不获得报告重试。宿主授权遭拒、取消或不可用时绝不分派 Headsman。失败 workflow 或 child 作为 `SpecialistExecutionFailure` 传播；驱动器在重新抛出前保存其已完成宿主质量记录的检查点，不添加合成 envelope 或门禁决策。角色是否启动取决于实际 child 生命周期事件；已接受或排队的 agent 调用不足以证明启动。即使资源释放失败，临时 workflow 观察者也会移除。现有完整沙箱和精确命令策略不变。

### 按门禁预算与持久化

`maxReworkPerGate` 取代整次运行预算。它是经验证的正安全整数；工具默认值和随附预设均为 2。`reworkCycles(run, gate)` 只计算 `GateRecord.gate` 匹配且决策为 rework 的历史记录。同一门禁允许两次返工，下一次请求转为 escalate，并在记录理由中注明已耗尽限制。其他门禁保持独立。Ralph Round 保持其单独的现有限制。

记录格式 2 保存重命名预算和 `report` 缺陷路由。解析器拒绝过时记录版本、已移除预算字段、超出各门禁限制的返工，以及被路由到另一角色的报告修复。不通过兼容层翻译旧的未完成运行。#30 设计可在此布局之后分配下一格式；此处不实现 intake 选择、分析终止、界面元数据或源码启动生成。

### 结果证据

阻塞和决策工具结果均包含运行 id、已达阶段、状态、含理由的完整门禁历史，以及真实运行时门禁尝试所代表的角色。被拒绝报告虽不进入已验证专家报告，仍保留对应角色。创建前错误明确说明没有启动运行；创建后基础设施错误附带最后持久化检查点及已确认启动但失败的子级，不编造门禁决策。GO 仍要求独立的所有者控制 closeout，每次结果后父级仍被拒绝工具。

### 保留决策与验证

保留有效的[运行时](../feature/2026-09-11-conductor-runtime-layer.md)、[quality-executor](../feature/2026-10-10-conductor-quality-command-executor.md)、[已安装 skill](2026-10-24-conductor-installed-skills.md)和[路由](2026-10-25-conductor-mode-routing.md)决策。其授权、隔离、安装及父级限制仍适用；本变更只调整报告修复、所有者路径构造、预算计数、持久化验证和状态报告。没有符合归档条件的说明。

聚焦测试覆盖第二次和第三次返工、独立门禁预算、同角色修正、格式错误嵌套字段、立即权限或批准故障、持久化质量证据、旧格式拒绝及真实工具结果。真实可运行的已安装预设 headless 示例覆盖 Gate C 路径提案被拒、全新报告修正及绑定所有者的 baseline，以及预算耗尽后仍保留已完成角色与门禁历史的阻塞结果。已有 closeout、Headsman/Ralph 质量及已安装资源快照保留其策略。Fixture（测试前置数据）在 Linux/WSL 录制；已有检查点仍携带不透明运行 JSON，不改变 SessionEventMap，因此通用 SDK 投影无需改变。

## 曾考虑的替代方案

- **接受或静默规范化模型编写路径字段：** 拒绝，因为模型仍在编写类似权限的数据。省略字段并明确拒绝，使其运行时所有权可见且可测试。
- **所有格式错误报告立即升级：** 拒绝，因为安全的有界重试存在时，可修复输出格式错误不应要求所有者介入。权限和证据违规仍立即升级。
- **按门禁限制之外保留整次运行预算：** 拒绝，因为一个门禁仍可耗尽另一个的修复次数，且新增可调项没有当前所有者需求。
- **同时构建 #30 intake 或只读完成：** 拒绝，因为它们独立改变阶段和终止语义。A–G、Ralph 及所有者授权的 closeout 保持不变。

## 后果

格式错误报告在每个门禁最多消耗两次全新 child 重试后升级，在增加 token 消耗的同时限制修复。操作者获得真实门禁路径，而不只是单句阻塞文本。旧的未完成记录需要新运行；所供计划或报告仍不能授予执行权限。随附空质量命令目录和现有平台沙箱限制不受影响。
