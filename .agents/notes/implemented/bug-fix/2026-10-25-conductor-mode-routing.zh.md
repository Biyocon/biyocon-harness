# Agent Note: Conductor 模式在工作区工具之前分派任务

Status: implemented

[English](2026-10-25-conductor-mode-routing.md) | 中文

## 问题

Conductor 预设将委派描述为可选行为。父级可以直接读取工作区并回答普通分析任务，而不启动专家。声称具有更高具体优先级的项目指令进一步强化了这一做法。工具失败后报告并停止只是提示词指引，因此父级也可能在运行受阻后自行继续。

## 决策

[应用预设](../../../../apps/cli/config/agent-presets/conductor/agent.cordis.yml)要求每项新任务的首次工具调用为 `conductor`，并启用[该工具](../../../../packages/conductor/tool-conductor/README.md)的 `routeTasks` 策略。父级转交目标与约束，不自行编造写入授权。其系统 persona 明确区分专家的工作区指引与模式路由。

Conductor 专用策略使用现有的 agent（智能体）、提示词组装和工具执行钩子。分派前只提供 `conductor`，执行器守卫拒绝其他工具。分派运行期间，以及返回失败或受阻结果之后，父级不能执行替代流程或自动重新分派，只能报告结果。未分派就结束任务会明确报错。新的用户轮次或用户 steering（中途引导）消息重置路由，插件上下文则不会。是否由 Arbiter 决策恢复父级原有能力，取决于最终工具结果，而不是工具正文的暂定返回。专家会话不受父级路由限制，继续使用原有的阶段执行器约束。注册随挂载的工具一同释放。

工具描述明确列出 supervisor、七位全新专家、门禁决策，以及按缺陷分类的返工路由。这涵盖 [issue #27](https://github.com/Biyocon/biyocon-harness/issues/27) 的第 4 点；运行时路径、报告验证、门禁预算及更完整的受阻结果渲染均不在本决策范围内。[Issue #26](https://github.com/Biyocon/biyocon-harness/issues/26)负责任务路由。#25 的源代码启动生成机制与 #28 的界面元数据也保持不变。

### 分析任务与阶段模型

分析没有单独的成功终止状态。它依次经过 Detective、Strategist、Devil's Advocate、Gate C 宿主批准、Headsman、Auditor、Integrator 和 Arbiter。空 `allowedPaths` 产生只读效果配置，不向 Headsman 或 Integrator 提供写入工具。如果每个角色均满足其阶段要求，完整分析可以仅通过报告、不修改文件，达到普通 Arbiter 决策；需要但缺少实现输入的角色，或遭拒绝的 Gate C 批准，则返回阻塞。父级报告这一限制，而不是自行完成分析。本次路由变更不承诺专用分析完成方式，也不跳过实现阶段。

后续设计可以引入显式只读目标类别，提供经评审的分析交付物，并通过专用分析转换进入独立评估和 Arbiter。这需要所有者批准阶段、报告与持久化设计，包括完成标准和快照；此处未实现。现有阶段、宿主批准、返工预算、Ralph Round 和 closeout 授权保持不变。

## 曾考虑的替代方案

**仅强化 persona。** 工作区指引或模型错误仍可能执行独立读取。执行器拒绝机制为提示词指令提供保障；无密钥示例同时验证向模型提供的工具和实际首次调用。

**修改通用工作区指令 loader。** 其他预设仍需要其正常优先级行为。Conductor 专用策略保持这些预设不变，并允许专家在原有能力范围内遵循项目指令。

**永久移除父级写入工具。** 这是 F07，属于独立的能力决策。本策略控制分派顺序和失败后的替代执行；Arbiter 决策返回后，原有能力及所有独立权限规则均保持不变。

**根据用户文本自动构造工具调用。** 这会绕过模型对范围和恢复字段的提取，或编造路径授权。模型通过现有的已记录工具流水线提供调用；跳过分派会明确失败，而不产生虚假的成功工作流。

## 后果

路由没有新增会话事件类型、SDK 字段或通用循环变更。工具可用性可从现有的已记录请求 header 重建。不遵循指令的模型仍可能输出文本或请求不可用工具；执行会被拒绝，且未分派的纯文本轮次会失败，而不是悄然完成任务。提示词和无密钥 fixture（测试前置数据）都不能证明真实模型的分析质量。

真实的 [headless 示例](../../../../examples/headless-agent/tests/conductor-installed.snapshot.ts)使用含有矛盾 AGENTS.md 指令的外部工作区，目标中不含 Conductor 一词。如果模型可见的工具包含读取工具，适配器就尝试自行读取。记录的父级以 `conductor` 开始；真实 Detective 读取标记并返回有意设置的阻塞。聚焦测试覆盖直接执行器拒绝、失败后的替代执行、新任务、用户 steering 与插件上下文的区别、专家独立性、GO 后能力不变，以及策略释放。

[安装 skill 决策](2026-10-24-conductor-installed-skills.md)仍负责资源所有权与挂载验证。[运行时决策](../feature/2026-09-11-conductor-runtime-layer.md)仍负责门禁、能力策略与所有者授权。两者均未被完全取代，因此保留并链接至这一更窄的策略；没有归档任何说明。
