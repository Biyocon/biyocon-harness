# Agent Note: 在源码启动时准备 Conductor 指令

Status: implemented

[English](2026-11-01-conductor-source-launch-assets.md) | 中文

## 问题

Conductor 的安装资源原先只由 CLI 构建生成。修改正典角色或协议后从源码重启，可能静默加载旧指令。先删除再重建活动 skills 目录，还会让并发读取者看到缺失或不完整的资源。

## 决策

[仅用于源码的入口](../../../../apps/cli/scripts/source-launch.ts)先等待[共用生成器](../../../../apps/cli/scripts/generate-conductor-skills.ts)完成，再导入普通 CLI。路径相对于安装位置，而不是任务目录。CLI 构建使用同一生成器；发布的 bin 不导入源码准备逻辑。生成失败时输出明确指向 Conductor 的诊断，并在 profile 启动前退出。[已安装 skill 的校验与路由规则](2026-10-24-conductor-installed-skills.md)仍然有效。

生成器先读取正典字节并与安装文件比较，再创建暂存输出。输入一致时不执行文件系统修改。变更文件在唯一的同级暂存目录中完整写入并关闭。首次安装通过一次 rename 发布完整目录。更新逐个替换文件，不删除活动目录：POSIX 使用 rename；Windows 对已有目标使用现有的 [ReplaceFileW 辅助函数](../../../../packages/fs/fs-local/src/win32.ts)，包括普通 Node 读取者仍持有的文件。全部替换成功后才 unlink 过期文件。每次调用仅清理自身的暂存目录。

针对同一未变更正典源的并发启动可以独立发布相同字节；发布者在替换前重新检查各目标。目录发布冲突转为逐文件发布，已被另一发布者删除的过期文件不构成错误。不重试失败的文件替换。禁止替换的 Windows 独占句柄会使生成停止，不触发删除或回退到旧指令。

## 考虑过的备选方案

**每次启动都构建。** 完整构建还会刷新无关的浏览器和包产物。准备指令只需要正典资源生成器。

**删除活动目录后重新复制。** 读取者可能看到缺失路径或尚未写完的文件，包括另一次源码启动或已有应用。

**所有 Windows 替换都使用 Node rename。** 原生 Windows 测试表明，目标存在且有 Node 读取句柄打开时，替换会以 EPERM 失败。现有原生辅助函数让该读取者继续读取旧内容，同时让新打开的句柄看到替换后的内容。

**重写相同文件或重试共享冲突。** 重写增加不必要的 I/O 并改变时间戳。重试掩盖共享和权限故障，却不能建立正确的发布行为。

## 后果

发布对单个文件具有原子性，不是横跨全部角色和协议文件的事务。现有预备定义不会热重载。正典编辑必须在启动前完成；并发编辑正典树不属于受支持的快照操作。浏览器产物仍需单独构建，详见[构建调度决策](../simplification/2026-08-12-separate-source-launch-from-build.md)。

源码回归测试使用独立 home 和外部工作区，覆盖首次生成、下一次启动读取新指令、并发进程、无效角色及生成失败即停止。发布测试强制写入者重叠，并在读取者持有旧文件时暂停替换；还验证输入不变时无修改，以及暂存或发布失败时原文件保留。[真实无头快照](../../../../examples/headless-agent/tests/conductor-installed.snapshot.ts)通过源码入口准备资源，并保留首次模型请求前拒绝缺失角色的检查。CLI 包冒烟测试验证随附资源与正典字节一致。原生 Windows CI 负责验证 Windows 内核上的打开句柄行为。
